# BLE 通讯标准

采用Bluetooth Smart (也称作BLE 或Bluetooth Low Energy)技术以peripheral模式实现与支持Bluetooth Smart技术的central终端进行数据交互。

Peripheral：智能硬件设备端，如吸奶器。

Central：控制终端，如APP、小程序等。

##  蓝牙标准

蓝牙标准 SmartReady v5.0。

##  BLE UART Server

UART Service是通过自定义UUID实现BLE SPP数据透传功能，通过LUTE私有协议对设备进行控制和数据传输，GAP（Generic Access Profile）、DIS（Device information Service）、BAS（Battery Service）采用Bluetooth SIG规范下的标准协议，进行蓝牙配对以及设备相关信息的读取，可参考BLE官方文档。

##  数据包格式介绍

一个完整的数据包格式定义如下：

| Protocol Packet Structure |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- |
| Start Of Packet<br>(SOP) | Frame Control Field<br>(FCF) | Command Type（CT） | Command ID(CID) | Command Argument（CA） |  | CheckSum8 |
|  |  |  |  | Command Argument Len<br>（CAL） | Command Argument Body<br>（CAB） |
| U8 | U8 | U8 | U8 | U8 | Variable | U8 |
| 0xAA | 0x55 | 0x00(REQ) | — | — | — | — |
|  |  | 0x01(ACK) |
|  |  | 0x02(NACK) |
|  |  | 0x03(Notify) |
|  |  | 0x04(Device) |

帧头SOP+FCF：0xAA 0x55

命令类型（CT）描述：

REQ：数据请求，需有ACK或者NACK应答；（该类型指令需要重传机制，暂定间隔3s，最多重传3次，失败则需要主动断开连接）

ACK：数据接收后正确应答，返回REQ所需数据；

NACK：数据接收否定应答，返回错误信息；

Notify：用于设备自动反馈数据，不需要ACK或NACK应答；

Device：用于设备硬件控制的上报数据，需有ACK或者NACK应答。

命令（CID）：详见命令指令ID部分。

命令参数长度（CAL）：1个字节，最大参数长度100字节。

命令参数数据（CAB）：字节数量等于CAL。

CheckSum8计算方法：数据包除校验字节本身外的所有数据按字节求和取反。（测试时可以使用0xFF代替）参考代码如下：

u8 check\_sum(u8 \*dat, u8 len)

{

    u8 i = 0;

u32 sum = 0;

for (i = 0; i < len; i++)

{

sum += dat\[i\];

}

    return ~(u8)sum;

}

##  协议兼容性补充说明

### 需求说明：

       自定义协议在产品开发过程中，随着功能增加和变化，设备的不同版本之间的协议可能会存在差异，这就可能出现兼容性的问题，导致设备的使用异常。

       为了解决这个兼容性的问题，需要有一条所有设备都会使用的命令，通过这个命令同步app和设备之间的协议版本，app会切换到相对应的协议版本，保证和设备的通讯正常。

       目前app在连接设备上之后，会先发送F0指令获取设备信息，所以就把F0指令进行一些优化，来满足兼容性的要求。

###  F0指令功能介绍：

        首先F0指令必须需要有回复，包括指令正确后的信息返回和指令错误后的提示，方便app在第一时间内进行处理。

目前的F0指令的格式不变，保证已经量产的设备可以兼容。

在F0指令中增加通讯协议版本的字段。

发送的F0指令中附带的流水号不正确，则返回NACK，在NACK中会有一个字节的error错误提示。

公司的所有智能硬件，必须支持F0指令，且F0指令原则上不加密。

###  F0指令安全性保障：

a. 对于app端，如果连接上ble之后，F0指令发回有错误，包括超时，格式错误等，app需要主动断开连接。

b. 对于设备端，在连接上ble之后，如果没有在规定时间内收到正确的F0指令，设备需要主动断开连接。

###  F0指令扩展性：

F0的发送中已经有4个字节的数据信息用于判断，不需要增加。

a.  F0指令的ACK返回可以扩展，但是原则上必须在已有的字段后面增加，不能在前面插入新字段。

b.   F0的NACK返回中有一个字节的error提示，足够提示错误类型。
