## Goal

对当前 App 进行一次完整的 UI / UX 页面盘点，将 **所有可访问页面、弹窗、浮层，以及用户操作后产生的各种界面状态** 全部梳理并输出为一套完整的页面视觉资产，确保后续可以基于这套资产逐页检查、重构和还原 App。

### 核心要求

请完整遍历当前 App 的所有一级模块、二级页面、三级页面及更深层级页面，不要只梳理主页面。

需要覆盖以下内容：

1. **所有独立页面**

   * 首页及各一级 Tab
   * 二级 / 三级详情页
   * 设置页、表单页、列表页、详情页
   * 登录 / 注册 / 授权 / 空页面等辅助页面
   * 所有可通过正常用户路径进入的页面

2. **所有弹窗与浮层**

   * Dialog / Modal
   * Bottom Sheet
   * Action Sheet
   * Picker
   * Toast / Snackbar
   * Tooltip
   * 权限申请弹窗
   * 确认 / 删除 / 退出 / 错误提示弹窗
   * 其他覆盖在页面上的交互层

3. **所有按钮及交互触发后的 UI 状态**

   不要只记录按钮本身，需要实际点击并继续梳理点击后的完整链路。

   例如：

   * 点击卡片 → 详情页
   * 点击“添加” → 表单页 / 弹窗
   * 点击“编辑” → 编辑状态
   * 点击“删除” → 二次确认弹窗 → 删除后的页面状态
   * 点击开关 → 开启 / 关闭状态
   * 点击 Tab / 筛选器 → 不同内容状态
   * 点击 CTA → 下一页面或业务流程
   * 提交表单 → 成功 / 失败 / 校验错误状态

   原则是：

   **只要用户的一次操作会改变当前界面，就需要将变化后的界面纳入梳理范围。**

4. **覆盖页面的主要数据状态**

   对同一页面存在明显 UI 差异的状态，需要分别输出，例如：

   * 初始态
   * 空状态
   * 有数据状态
   * Loading
   * Error
   * 已完成状态
   * 未购买 / 已购买
   * 未授权 / 已授权
   * 未登录 / 已登录
   * 未填写 / 已填写
   * 无进行中任务 / 有进行中任务

   无需为了覆盖而人为制造没有实际产品意义的状态，但所有当前产品已经支持的状态都必须覆盖。

## 页面截图要求

每一种独立页面 / 独立 UI 状态都需要生成对应截图。

### 普通页面

直接输出完整页面截图。

### 可滚动长页面

如果页面内容超过一屏：

**不要只截首屏。**

需要生成完整的 **纵向长图截图**，从页面顶部一直覆盖到页面底部，保证完整展示：

* 页面顶部
* 中间所有模块
* 页面底部内容
* Bottom Navigation 之前的全部内容

如果无法一次生成长截图，可以通过多张截图拼接生成最终长图。

## 执行原则

执行过程中不要仅通过阅读代码推断页面。

需要尽可能 **实际运行 App 并操作 UI**，沿真实用户路径遍历产品，因为部分页面或状态可能：

* 由条件判断动态显示
* 只有点击后才出现
* 依赖已有数据
* 依赖登录状态
* 依赖购买状态
* 依赖权限状态

代码分析可以辅助寻找遗漏入口，但最终应以 **实际运行结果** 为准。

对于代码中存在、但目前无法通过正常 UI 路径进入的页面，也需要单独记录，并标记：

> 当前代码存在，但暂无正常用户入口

---

## 完成标准

任务完成前请检查：

* 所有一级模块均已覆盖
* 所有可点击入口均已遍历
* 所有重要弹窗均已覆盖
* 所有关键状态均有截图
* 所有长页面均提供完整长图
* 不存在“只截主页面、不继续点击”的情况
* README 中能够完整追溯页面之间的跳转关系
* 截图命名统一且能够和页面清单一一对应

最终目标不是简单截几张 App 页面，而是建立一套：

**当前 App 的完整 UI / UX 状态地图（UI Inventory），完整覆盖 Page × State × Interaction。**
