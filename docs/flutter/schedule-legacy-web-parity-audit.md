# 计划页旧 Web 对齐专项审计

## 目标与基准

目标是让 Flutter `计划` 页在信息层级、文案、控件形态、交互路径、动效和弹层体验上与 `legacy_web` 保持一致，同时保留 Flutter 已经具备的生产级正确性保障。

基准实现：

- 页面：`legacy_web/src/pages/Schedule.tsx`
- 添加任务：`legacy_web/src/components/schedule/AddTaskDialog.tsx`
- 时间选择：`legacy_web/src/components/schedule/TimeWheelPickerSheet.tsx`
- 提醒确认：`legacy_web/src/components/schedule/ReminderAlert.tsx`
- 吸奶补录：`legacy_web/src/components/records/ManualEntryDialog.tsx`
- 喂养记录：`legacy_web/src/components/baby/FeedingEntryDialog.tsx`
- Flutter 页面：`flutter_app/lib/features/schedule/presentation/schedule_dashboard_page.dart`

## 对齐边界

必须对齐：

- 首屏信息顺序、间距、字号、圆角、色彩层级和按钮密度。
- 日期浏览、回到今天、提醒开关、Agent 对话、任务说明、任务增删改、任务完成、补录和截图识别的交互路径。
- 底部抽屉、时间选择器、确认弹窗、加载/空/失败反馈和转场动效。
- 今天、过去、未来、有任务、无任务、全部完成、部分跳过等状态文案。

必须保留：

- 后端权威响应后才显示写入成功。
- 创建和补录请求的幂等键。
- 账号隔离的提醒偏好、Android 系统提醒同步和同步失败的真实反馈。
- route intent、计划变更高亮、跨 Tab 内存状态、无障碍语义和 reduced motion。
- 部分接口失败时继续展示仍然可用的数据，不伪造成功或静默丢失错误。

## 推进顺序与验收

1. 日期导航与页面骨架
   - 验收：360、390、430 宽度均显示完整 7 天；回到今天不挤压月份；切周不请求、选日才请求。
2. 摘要、Agent、Hero、工具栏和内容顺序
   - 验收：首屏信息顺序、文案和组件尺寸与旧 Web 契约一致；无文本溢出。
3. Timeline 和任务操作
   - 验收：来源、完成、跳过、关联记录、删除与编辑均可用；任务行保持紧凑。
4. 添加任务、时间选择、提醒、说明与记录抽屉
   - 验收：所有旧 Web 弹层路径均可达；关闭/取消不写数据；提交只发生一次并等待权威响应。
5. 加载、空、失败、通知与跨 Tab 状态
   - 验收：错误反馈真实但不阻断可用内容；提醒、route intent 和计划更新高亮无回归。
6. 视觉与全量回归
   - 验收：三档页面 golden、组件 golden、schedule feature、路由集成、`flutter analyze` 和全量 `flutter test` 通过。

## 基线结果

- 旧 Web：`Schedule.test.ts`、`ScheduleTodayTaskExplanation.test.ts`、`planNotification.test.ts` 共 10 项通过。
- Flutter：`test/features/schedule` 与 schedule component golden 共 73 项通过。
- 当前执行环境没有可用的内置浏览器实例，旧 Web 视觉参数以实际 DOM/Tailwind 源码为基准；Flutter 结果通过 360x800、390x844、430x932 三档 golden 固化。

## 自审结论

方案按“页面结构 -> 高频操作 -> 弹层 -> 异常状态”推进，先处理用户每次进入都会看到的偏差，再处理低频路径。实现只调整 presentation 和对应测试；controller、repository、幂等与提醒网关契约不做无关重构。该方案能够实现旧 Web 体验对齐，同时避免回退已经建立的生产正确性。
