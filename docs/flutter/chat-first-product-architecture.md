## 契约决策与存量兼容

- 新建 `/v1/onboarding/me/chat-first` 的 GET/PUT：GET 区分 `required/completed`、`can_enter_app`、家庭角色和 `profile_scope`（未采集／新流程部分资料／旧完整档案），可返回已有 `primary_infant_id`，但不假设宝宝存在。PUT 对妈妈要求 Demo 实际采集字段；其他角色只保存角色。事务内完成资料与关注点写入、幂等判定和审计。
- 旧 `/v1/onboarding/me`、`PUT .../profile` **保持现有输入和读取语义**；新流程不会创建假的姓名、喂养方式或宝宝档案。旧版已有完整确认映射为妈妈可进入新 App；新的部分确认不使旧版误判为完整档案。旧版在新账号上仍可能要求其原有附加资料；这属于兼容窗口而非假数据迁移。
- 后端需新增权威的按账号完成记录（迁移、owner 锁、冲突与回放语义）；个人年龄、分娩信息与关注点沿用可供 Agent 读取的现有结构。旧用户无需清空原档案，妈妈展示白板前还须读取实际日期与时区条件。
- 认证、跨账号缓存清理、深链、通知、历史数据和旧版本客户端是回归约束。任何 Agent 上下文修改必须根据真实读取契约评估后再做。

| 换尿布、睡眠 | `POST /v1/babies/{baby_id}/records`；选中宝宝 ID 与 `Idempotency-Key` | 只有已创建且选中的真实宝宝才能保存；否则禁用保存并提供创建宝宝档案入口。成功响应须回显同一宝宝与记录 ID。 |
| 听哭闹 | 本地录音、试听，Product Backend 独立识别服务与结果卡已接入代码；真实哭声样本与设备验收仍待完成 | 上传前将随机操作键和已提交会话 ID 写入账号级安全快照；Product Backend 先返回 `pending`，App 按键查询 `done`/`incomplete`/`failed`，离页后可恢复已完成的结果。Backend 保存所属会话，换机可按用户和会话取回最近 100 条结果卡。音频只上传 Product Backend，不作为 Agent 附件；Agent 只按 `analysis_id` 读取用户/会话绑定结果。处理中任务为服务进程内短期任务，重启后最多五分钟标记失败、需重新录制；真实哭声分类与双区域环境尚未验收。 |
| 看便便 | 现有照片/PDF 上传及 Agent 会话契约 | 可附照片或文字；仅展示真实 Agent 回复，不把它伪称为确定性图片识别或医学诊断。 |
