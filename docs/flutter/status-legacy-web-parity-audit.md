## 有意差异与验证边界

1. 旧 Web 宝宝睡眠报告的前一天/后一天按钮没有实际数据切换。Flutter 保留视觉入口但明确禁用，不复制无效交互。
2. 安全区、系统返回、键盘收起和下拉刷新采用 Flutter 原生行为，不逐像素复制浏览器容器行为。
3. 旧 Web 本身使用展示数据的乳房健康、康复、宝宝健康、milestone 和睡眠模块仍保持只读展示，不伪造后端写入成功。
4. 自动化视觉门禁已覆盖 Flutter 三档屏宽和旧 Web 同源 fixture 的结构/文案契约；当前执行环境没有可用的应用内浏览器连接，因此同一实体设备上的旧 Web/Flutter 人工并排截图仍是发布前验收项。

## 初始审计结论（历史）

Flutter 已具备阶段切换、妈妈/宝宝身份卡、四宫格卡片、孕期日记/计划外壳和趋势区域，但当前实现主要是静态空态近似。真实数据、保存流程、底部抽屉、完整详情、图表语义、通知联动和多数失败状态尚未对齐。

当前最重要的结构性问题：

1. `_StatusPage` 和大量私有组件位于超过一万行的综合页面文件中，数据加载、页面状态和展示代码混在一起。
2. `StatusOverview` 仅包含妈妈阶段、产后天数、宝宝昵称和年龄，无法表达旧 Web 页面所需的数据状态。
3. Flutter 只读取 `/v1/profile/me` 与 `/v1/profile/infants`；页面其余指标多为硬编码或本地布尔值。
4. 现有 Golden 是 Flutter 自身截图基线，不是旧 Web 与 Flutter 的跨实现对比。
5. 现有 Widget 测试主要断言文本或组件存在，静态假数据也可能通过。

## 数据与架构方向

1. 将 Status 页面和组件迁入 `features/status/presentation/`，综合页面文件只保留路由装配。
2. 扩展 `features/status/domain/`，用不可变 typed model 表达每个模块的 loading/data/error 与 mutation 状态。
3. 继续使用当前 `ApiJsonTransport`、session 和 runtime 注入，不引入第二套网络或状态管理框架。
4. 复用并扩展 `RecordsApiRepository`，补齐 `head_cm`、创建和修改成长记录能力。
5. 新增 typed `PregnancyDiaryRepository` 与计划读取/更新适配层，严格按当前 OpenAPI 契约实现。
6. 页面 controller 统一协调首次加载、刷新、保存、乐观更新和失败回滚；Widget 不直接拼 API payload。
7. 健康、康复、睡眠等旧 Web 本身为演示数据的模块保持展示数据，不伪造后端写入。

## 测试与视觉门禁

- Repository：success、partial、empty、HTTP error、旧字段兼容、写入 payload。
- Controller/domain：阶段切换、聚合计算、单位换算、加载/错误、乐观更新与回滚。
- Widget：三个页面分支、所有详情入口、完整表单、保存状态、折叠、禁用和系统返回。
- Router/integration：Agent prefill/auto-send、原生 intent、跨 Tab 保留、账户切换。
- Golden：`360x800`、`390x844`、`430x932` 的孕期妈妈、哺乳期妈妈、哺乳期宝宝及关键底部抽屉。
- 视觉审查：同一 fixture 下分别截取旧 Web 与 Flutter，逐项核对结构、文案、组件尺寸和首屏/滚动位置；Flutter 自身 Golden 不能替代跨实现对比。
