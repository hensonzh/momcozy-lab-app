# Momcozy App UI/UX V3 更新方案

> 文档状态：方案稿 v1.0
> 更新日期：2026-08-07
> 适用仓库：MomCozyApp
> 目标：将 0806 新视觉体系更新到现有 Flutter App，同时保留已上线的业务能力、数据真实性与安全边界。

## 1. 结论摘要

本次不应按设计切图重做一套静态页面，而应采用“统一设计系统、复用现有业务层、按业务切片逐步替换表现层”的方式升级。

建议的产品结构为五个一级入口：Me、Baby、Cozymate、Plan、More。首期优先完成全局导航、Me/Baby 数据化首页、Plan 日程能力和 Cozymate 三类核心服务；孕期、备孕、身体档案和大量二级数据页在临床文案、数据合同与隐私方案确认后分批上线。

核心判断如下：

1. `MeBabyOverviewPage` 已经较高程度还原 Me/Baby 新视觉，可作为迁移起点；Header 生命周期切换已接入账号级 profile 状态，但新增按钮和部分二级数据仍需接入业务合同。
2. 现有 `ScheduleDashboardPage` 已有日程增删改查、任务状态、加载/错误/空态和失败反馈，不应推倒重写；应把其业务能力装入新 Plan 信息架构。
3. 现有 Agent Hub 已有流式会话、引用、结构化卡片、交互持久化和计划变更接入，主要缺口是视觉分层与三类服务的标准交互协议。
4. 当前底部导航的 Plan、More 为不可点击占位，需要首先补齐路由、选中态、返回栈与状态保持。
5. 四个 UI 目录含大量重复页面截图和组件截图，不能整体作为运行时资源提交。App 只应保留经过筛选和优化的独有插画、头像、照片或复杂纹理。

## 2. 需求范围与边界

### 2.1 本次覆盖

- Me：产后泌乳、产后恢复概览，头像展示模式，数据详情入口。
- Baby：监护、睡眠、喂养、尿布、成长概览与记录入口。
- Cozymate：
  - 基于知识库的母婴健康咨询问答；
  - 日程增删改查；
  - 打开泌乳计划创建入口并管理计划状态。
- Plan：统一承载日程任务和泌乳计划状态，不把两者混为一个对象。
- More：承接设备、社区、账户、设置和暂未进入一级导航的现有功能。
- 新版全局导航、设计令牌、通用卡片、图表、表单、底部弹层和反馈状态。
- 现有孕期日记与孕期计划继续作为 Cozymate 能力保留；孕期计划通过当前对话中的结构化卡片查看和管理，孕期日记通过对话完成操作反馈。两者不再同步到 Me/Baby 页面，也不在 App 建立无页面消费者的本地镜像状态。

### 2.2 明确不做

- 智能体不生成、改写或决定泌乳计划内容；创建内容由专门的泌乳计划流程负责。
- 不根据聊天文本自行推断“计划已创建/已生效”，计划状态必须来自服务端或受控状态合同。
- 不将设计稿中的示例数值、人物信息、摄像头画面或健康结论带入生产。
- 不把“正常、健康、一定够奶”等结论仅凭单个数值展示给用户。
- 不把 4x 全屏稿、组件截图、状态栏、系统键盘、文字切片等作为 Flutter 页面素材。

## 3. UI 资产浏览与版本判断

项目根目录保留两个 0806 UI 目录。浏览结果如下：

| `MomcozyAI主要页面0806/` | 45 PNG，约 15 MB；32 个去分辨率后的页面名 | Me/Baby、孕期/备孕、Cozymate、Plan、数据详情、身体档案、品牌规范 | **主页面与产品行为的主参考** |
| `MomcozyAI切图0806/` | 409 PNG、266 SVG，约 98 MB | 头像族、插画、图标、卡片与大量组件截图 | **独有视觉资产候选池** |

### 3.1 已覆盖的页面族

- Me 首页：Lactation、Recovery、头像全屏态。
- 生命周期：Fertility、Pregnancy、Postpartum Recovery 选择器及孕期头像态。
- 身体档案：恢复档案概览、盆底/腹直肌/疼痛地图录入。

- Cozymate：长对话、消息气泡、引用、图表、报告、推荐动作和输入区。
- Plan：空态、单类别计划、多类别周计划、任务进度和计划设置。
- 记录与详情：奶量、睡眠、饮水、体重、母亲/宝宝新增记录弹层。
- 设计规范：颜色、字体、按钮、输入、导航、卡片、日历、状态标签、进度和数据图表。

### 3.2 设计稿内部需要先消除的不一致

- 主品牌色至少出现 `#7A2840`、`#862644`，现有 App 全局主色又是 `#A86172`。
- 产品名同时出现 `Cozymate`、`CozMate`；现有中文页面还使用“智能体”。
- 设计规范使用 Rubik/Figtree，工程目前只有 Quicksand/NotoSansSC。
- 有些页面使用黑色主按钮，有些使用深玫红主按钮，缺少明确的动作层级规则。
- 部分稿件默认展示 11px 文字、密集标签和低对比度说明，不适合直接作为无障碍标准。
- Plan 稿中的 `Adjust with AI` 与“智能体只管理泌乳计划状态”的业务边界冲突。

```text

│   ├── 产后：泌乳 / 恢复
│   └── 数据详情与新增记录
├── Baby (/baby)
│   ├── Monitor / Sleep / Feeding / Diaper / Growth
│   └── 数据详情与新增记录
├── Cozymate (/)
│   ├── 健康知识问答
│   ├── 日程管理
│   └── 泌乳计划入口与状态管理
├── Plan (/schedule)
│   ├── 日程：日 / 周 / 月、任务 CRUD
│   └── 泌乳计划：入口、当前状态、里程碑与历史
```

### 5.1 导航原则

- 中间 Cozymate 保留强化视觉，但点击区域、语义和其他 Tab 一致，不遮挡页面内容。
- Plan 直接复用 `/schedule`，并补选中态；More 新增 `/more` 聚合页。
- `/me` 和 `/baby` 是唯一的母婴首页；路由层仅为已发布版本的外部链接保留不可见的 `/status` 到 `/me` 重定向。
- 一级 Tab 切换应保留各自滚动、筛选和子路由状态。短期可沿用当前 Shell，完成回归测试后迁移到有状态分支导航。
- 详情页隐藏或保留底栏必须统一定义，不能由单页临时决定。

## 6. 视觉与设计系统

### 6.1 推荐令牌

以品牌规范卡为基准，先建立语义令牌，不允许页面直接散落十六进制色值：

| 语义 | 推荐基准 | 使用规则 |
| --- | --- | --- |
| Brand / Deep Rose | `#7A2840` | 品牌强调、选中态、关键进度；需与 `#862644` 做设计确认后冻结 |
| Ink / Obsidian | `#1A1A1A` | 标题、正文、黑色主行动 |
| Background / Warm Cream | `#FBF5F3` | 页面背景 |
| Surface | `#FFFFFF` | 卡片、弹层、输入面板 |
| Rose Tint | `#F5E6EB` | 轻强调背景，不承载低对比正文 |
| Success | `#4CAF50` | 已完成/稳定；不能表示医学“正常”结论 |
| Warning / Danger | 新增语义令牌 | 风险和失败必须同时有图标/文字，不能只靠颜色 |

工程实现上，将现有 `momcozy_design_system.dart` 作为兼容门面，逐步把颜色、排版、间距、圆角、阴影和组件迁入 `lib/app/design_system/`。`_MeBabyOverviewColors`、`_MeBabyOverviewText` 不再继续扩展，新组件只能引用全局令牌。

### 6.2 字体

- 目标视觉可使用 Rubik 作为拉丁数字与大标题、Figtree 作为拉丁正文、NotoSansSC 作为中文回退。
- Rubik/Figtree 尚未进入仓库，必须先确认授权、字体包体和中文混排效果。
- 字体确认前，首期继续使用 Quicksand + NotoSansSC，避免同一版本出现三套字体。
- 所有文案进入本地化资源；日期、周起始日、单位、12/24 小时制跟随地区设置。

### 6.3 组件规则

- 页面水平边距统一为 16 logical px；密集图表可降到 12，但不得由切图决定。
- 卡片建立 `standard / tinted / warning / action` 四类语义，不按页面复制样式。
- 主要点击区域不小于 44×44 logical px。
- 不使用 Emoji 作为长期功能图标；优先 Material/SVG 图标系统，确保轮廓和填充态成对。
- 11px 只允许非关键装饰标签；核心正文不低于 14px，并支持系统字体放大。
- 图表同时提供标题、单位、时间范围、数据更新时间和文字摘要，颜色不是唯一编码方式。
- Bottom Sheet 统一有标题、关闭、取消/确认、键盘避让、拖拽提示和提交状态。

## 7. 各区域 UI/UX 方案

### 7.1 Me

首屏结构：品牌 Header → 生命周期选择 → 用户/头像 Hero → 数据分类 → 核心指标卡 → 服务入口。

- 默认进入“数据模式”，优先让用户看到今日奶量、恢复记录等可行动信息。
- 头像全屏作为可选“陪伴模式”，提供明确的“查看形象/查看数据”按钮；保留手势作为快捷方式但不能成为唯一入口。
- Hero 随滚动收缩为紧凑 Header，减少头像长期占据首屏。
- Lactation 展示今日奶量、目标、趋势、设备连接和最近记录；无设备时显示“手动记录”，而不是伪造连接状态。
- Recovery 的分数必须有计算依据、数据完整度和更新时间；没有受审查的算法时只展示已确认记录，不展示综合健康分。
- 黑色浮动新增按钮打开 Me 专属记录弹层，入口项目来自能力配置，不展示尚未可用的假按钮。
- Fertility、Pregnancy 先上线账号级阶段切换、诚实空态和已有 Plan/Cozymate 入口；周期预测、孕期里程碑和 Body Profile 仍作为后续能力，不展示设计稿演示数值。

### 7.2 Baby

首屏结构：Baby Hero → 分类标签 → 当前分类主卡 → 最近活动 → 新增记录。

- Monitor 中的摄像头画面必须来自真实设备状态；无权限、离线、未绑定、加载失败分别展示不同状态。
- Sleep、Feeding、Diaper、Growth 使用同一个时间范围选择器和图表容器，避免每页重新发明交互。
- “奶量足够”“成长正常”等表达改为“基于已记录数据的参考摘要”，并显示数据范围、来源和局限。
- WHO 曲线或百分位必须带标准版本、性别/年龄条件、更新时间和“仅供趋势参考”的说明。
- 添加记录后就地刷新，并提供可撤销反馈；删除和会影响照护判断的修改必须确认。
- 宝宝头像、族裔或外观由用户主动选择，绝不由照片、姓名或地区推断。

### 7.3 Cozymate

Cozymate 页面采用“对话 + 结构化行动卡”的布局，不复制稿件中的营销式长报告。统一名称使用 **Cozymate**。

#### 健康知识问答

- 回复由简短结论、解释、下一步、来源和安全提示组成。
- 知识库引用显示标题、来源、更新时间，点击进入现有媒体/外链查看能力。
- 数据不足时先说明不确定性，禁止以通用知识覆盖用户缺失的关键事实。
- 出现母亲/宝宝高风险信号时中断普通建议，展示专业就医或紧急帮助入口。

#### 日程增删改查

- 查询结果使用日程卡；新增/修改/删除使用“动作预览卡”。
- 预览卡至少展示对象、原值、变更后值、日期时区和影响范围。
- 用户确认后才执行；成功卡展示最终服务端状态，失败卡保留原状态并提供重试。
- “删除下午 2 点吸奶任务”若匹配多个任务，先展示候选项，不静默选择。
- 删除后的短时撤销仅在后端支持幂等恢复时提供，不能用纯本地假撤销。

#### 泌乳计划

- 智能体只提供“打开创建流程”和“管理计划状态”两类动作。
- 计划内容的生成、编辑、目标计算和专业建议均留在专门的计划流程中。
- 设计稿中的 `Adjust with AI` 替换为“询问 Cozymate”或“管理计划状态”，不得暗示智能体会改写计划。
- 计划状态卡必须基于结构化状态，建议至少覆盖：未创建、创建中、待确认、执行中、已暂停、已完成、已取消、失败。
- 任何状态变更先预览、后确认，并展示操作者、时间和失败恢复路径。

### 7.4 Plan

Plan 一级页面内部使用“日程 / 泌乳计划”分段，避免把任务状态和计划生命周期混成一套状态。

#### 日程

- 保留现有日期条、下一任务、任务列表、增删改查、完成/跳过/延后和记录能力。
- 视觉更新为新稿的周导航、分类标签、进度卡和任务卡，但控制器与 Repository 继续复用。
- Day/Week/Month 是查看范围；Lactation/Yoga/Pelvic Floor 是任务类别，两者不能放在同一筛选层级。
- 空态说明当前筛选条件，并提供“添加任务”和“让 Cozymate 帮我处理日程”两个真实入口。

#### 泌乳计划

- 未创建：显示计划价值说明和“创建泌乳计划”，跳转专门创建入口。
- 创建中/待确认：显示当前步骤和“继续创建”。
- 执行中：展示计划周期、当前里程碑、今日关联任务和状态操作。
- 暂停/完成/取消/失败：展示原因、时间和允许的后续操作。
- 计划详情只读展示服务端内容；状态管理与内容编辑分开授权。

### 7.5 More

More 使用简单分组列表，不复制首页卡片密度：

- 设备：设备连接、设备管理、提醒。
- 服务：社区、IBCLC 等已确认可用入口。
- 账户：个人资料、单位、语言、通知、隐私与退出。
- 开发调试入口只在开发环境显示，不能出现在生产 More 页面。

## 8. 页面状态与反馈规范

每一个数据页面和写操作都必须定义以下状态：

| 状态 | UI 行为 |
| --- | --- |
| Loading | 使用保持布局的骨架，不显示示例业务数值 |
| Empty | 解释缺少什么，并给一个可执行的主入口 |
| Error | 说明影响范围、保留最后可信数据、提供重试 |
| Offline | 标记离线及缓存时间，禁用不能离线执行的写操作 |
| Stale | 显示“更新于…”，不把旧数据包装成实时数据 |
| Permission denied | 解释需要的权限及用途，提供系统设置入口 |
| Mutating | 锁定重复提交，显示作用对象和进度 |
| Success | 以服务端回包为准，给结果和下一步 |
| Partial success | 清楚列出成功项和失败项，允许只重试失败项 |

## 9. Flutter 落地架构

### 9.1 原则

- 保持 feature-first 结构，不为纯 UI 升级引入新的全局状态框架。
- 复用现有 Runtime、Repository、Controller、ChangeNotifier 和 API 合同。
- Widget 只渲染 ViewState 并发出 Intent，不能直接拼 HTTP 或把示例数据当默认值。
- 仅当组件在两个及以上页面复用时进入公共设计系统，避免一次性抽象所有设计稿元素。

### 9.2 建议目录

```text
lib/
├── app/
│   ├── design_system/
│   │   ├── tokens/
│   │   ├── theme/
│   │   └── components/
│   └── momcozy_design_system.dart   # 兼容导出门面
├── features/
│   ├── profile_overview/                      # Me/Baby 业务和数据
│   │   └── presentation/v3/
│   ├── agent_hub/                   # Cozymate 与结构化服务卡
│   ├── schedule/                    # 日程 CRUD
│   ├── lactation_plan/              # 计划入口/状态视图，不含 Agent 内容生成
│   └── more/                         # 二级能力聚合
```

### 9.3 当前代码的具体改造点

## 10. 资产治理

### 10.1 可进入 App 的资产

- 独有 3D 人物/宝宝头像及经产品确认的变体。
- 摄像头占位、服务插画等无法合理用 Widget/SVG 绘制的视觉素材。
- 通过授权检查、裁剪空白、尺寸优化和透明边缘检查的图像。

### 10.2 不进入 App 的资产

- 全屏页面稿、品牌规范长图、完整聊天/计划截图。
- Header、BottomTabBar、Button、Card、StatusBar、文字、图表等组件截图。
- 同一内容的 1x/2x/3x/4x 无差别重复副本。
- `.DS_Store`、设计工具临时文件和不可识别命名的重复切片。

### 10.3 处理流程

1. 以 0806 主页面目录建立“页面—组件—资产”清单。
2. 对切图做哈希去重和视觉去重，只保留原始质量最好的源文件。
3. 将运行时图片转为合适尺寸的 WebP/PNG；图标优先使用 Flutter Icon 或清理后的 SVG。
4. 统一命名为 `feature_purpose_variant.ext`，放入具体 feature 资产目录。
5. 在资产清单记录来源、授权、使用页面、像素尺寸、压缩后体积和替代文本。
6. 原始设计稿保留在设计交付系统或大文件存储；若必须入 Git，应单独使用 Git LFS，不和运行时资产混放。

当前四个目录都应继续保持未跟踪状态，直到完成筛选；不要直接把约 220 MB 的设计交付物加入普通 Git 历史。

## 11. 安全、隐私与可访问性

- 健康卡片展示数据来源、采集时间、缺失项和参考性质；风险文案需产品与临床审核。
- 身体档案、疼痛地图、宝宝成长和摄像头均为敏感数据，不写日志、不进通用埋点参数、不出现在未授权通知预览。
- 恢复评分、成长百分位、排卵概率等派生结论在算法与临床依据确认前不上线。
- 头像族裔/外观仅供用户主动选择，不做自动推断。
- 关键流程支持屏幕阅读器、焦点顺序、200% 字体放大和横竖屏安全区。
- 正文与背景对比度达到 4.5:1，大号文字达到 3:1；风险与状态不能只用颜色表示。
- 动画尊重“减少动态效果”；头像大图和视频在弱网、低电量或低性能设备可降级。

## 13. 验收标准

### 13.1 功能

- 五个底部入口可达、可返回、选中态正确，关键页面状态在 Tab 切换后保留。
- Me/Baby 不显示硬编码示例业务数据；缺数据时显示真实空态。
- 日程查询、新增、修改、删除、完成、跳过均可从 Plan 和 Cozymate 正确执行。
- 所有日程写操作先预览和确认，多个匹配项不会被静默处理。
- Cozymate 健康回答可展示知识来源和安全边界。
- Cozymate 只能打开泌乳计划创建流程和改变允许的计划状态，不能编辑计划内容。
- 计划状态以服务端回包为准，失败不会误显示成功。

### 13.2 视觉与可访问性

- 关键页面覆盖 360、390、430 logical px 宽度及常见安全区。
- 200% 字体下核心任务不截断、不遮挡、可完成。
- 所有主要点击区域至少 44×44 logical px，屏幕阅读器语义和焦点顺序正确。
- 浅玫红背景、灰色说明、图表和禁用态通过对比度检查。
- 不把状态栏、导航、文字、按钮或图表截图作为运行时组件。

### 13.3 质量与性能

- Design System 和关键页面有 Widget/Golden 测试；日程、计划状态和 Agent 确认流有集成测试。
- 覆盖 loading、empty、error、offline、stale、permission denied 和 partial success。
- 图片进入首屏前完成裁剪与压缩；列表使用懒加载，头像大图有内存降级策略。
- 在目标中低端真机建立帧耗时和内存基线，新 UI 不得出现持续掉帧或图片解码峰值。
- 埋点只记录页面、动作类型、状态和耗时，不记录健康正文、疼痛位置、宝宝数值或聊天内容。

## 15. 推荐首个实现切片

首个垂直切片选择“Plan 导航 + 删除下午 2 点吸奶任务”：

1. 启用底部 Plan 并正确进入现有 `/schedule`。
2. 用 V3 Header、日期条和任务卡包装现有日程数据。
3. 在 Cozymate 输入“帮我删掉下午 2 点的吸奶任务”。

5. Plan 页面立即显示服务端最终状态；失败时保留任务并可重试。

该切片能同时验证全局导航、设计系统、Agent 结构化动作、日程业务复用、确认机制、跨 Tab 状态同步和错误恢复，是风险最低且最能证明新架构有效的一条路径。
