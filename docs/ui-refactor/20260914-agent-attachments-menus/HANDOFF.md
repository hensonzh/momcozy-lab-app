# 聊天附件与消息菜单

已完成 [17 个已有截图状态](source-inventory.json) 对应的附件入口、待发送图片和文件、已发送文件与图片元数据、用户和 AI 消息菜单，以及复制反馈。先在 [Figma](https://www.figma.com/design/ePIoJkiMiXiug9ibpcgRbl?node-id=259-1097) 创建 [22 个状态画板与 1 个共享组件](figma-nodes.json)，检查后落实到 Flutter。普通和大字号均有对应设计。

附件菜单采用奶油表面、薄荷图标区、15 字号入口和 12 字号格式说明，保留相机、照片和 PDF 的原有入口及可用条件。待发送附件继续横向滚动；文件名升为 14 字号、最多两行，大小为 12 字号。大字号下预览与移除按钮在一行，名称和大小在下方，保留完整文件名提示和 44 触控区。已发送文件和图片名称允许完整换行，图片仍按原逻辑加载缩略图和原图。共享 Figma 组件为 MomCozy/AttachmentDraft（259:1096），Flutter 继续复用 AgentAttachmentTile 与 AgentAttachmentMetadata。

消息菜单沿用原生弹出菜单的定位、键盘与辅助功能入口，改用共享表面、边框、青色图标和 NotoSansSCHome。菜单只有原有的复制与条件性重试；复制成功／失败反馈沿用原文，采用深色背景与统一字体。

本轮修复了源截图已记录的系统返回键失败。真实 ShellRoute 在显示驻留聊天页时没有挂载其内层 Navigator，GoRouter 处理返回键因此出现空值错误。现在内层 Navigator 保持挂载，在聊天页期间隐藏、停用焦点和动画；聊天路由的内层页面使用占位，避免重复创建第二个聊天页。驻留聊天实例、切换会话与草稿保持原机制。

验证结果：

- [返回键回归修复前失败](menu-back-red.log)，393×844 / 1× 与 320×844 / 2× 均复现空值错误；[修复后通过](menu-back-green.log)。最终测试还验证仅存在一个聊天页、菜单关闭后目标会话不变，以及原有通知已读、历史读取、两会话草稿隔离与新登录 runtime 隔离。
- [213 项最终联测通过](joint-tests.log)，不启用更新基线。覆盖附件选择、上传锁定、移除与清理失败、发送及缓存恢复，复制原始文本、失效消息保护、重试条件、图片加载／重试／缩放、通知路由、导航和路由契约。
- 路由挂载调整另外通过 [15 项引导路由与能力开关检查](route-gate-tests.log)，确认已有入口限制、头像任务返回和日程能力配置保持正常。
- [8 个修改文件静态分析通过](analyze-final.log)。[7 项行为对比通过](behavior-checks.json)：聊天生命周期与请求／上传／移除／发送流程、输入控件和发送条件、图片加载和全屏查看器、复制重试分派、菜单可用条件、键盘及辅助功能入口、文件大小格式保持不变。路由挂载修复单独由上述真实路由测试保护。

更新基线前已核对视觉差异。附件和菜单设计检查覆盖 320/390/430 宽度、1×/2× 字号及 568 高短屏；另新增普通及大字号复制失败→重试成功反馈截图。图片测试的全屏场景通过仅代表交互未回归，不代表全屏查看器视觉重构已完成。
