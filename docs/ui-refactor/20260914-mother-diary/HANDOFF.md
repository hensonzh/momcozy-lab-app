# 身体、心情与休息记录

基于 [238 个已有截图状态](source-inventory.json)，完成 `/me/diary` 页面及妈妈页共用记录弹窗的 UI 重构。先在 [Figma](https://www.figma.com/design/ePIoJkiMiXiug9ibpcgRbl?node-id=306-1086) 设计三分区表单、可选字段、联动问题、加载、校验、保存失败与冲突、长备注及离开确认，再落实 Flutter。[47 个 Figma 节点](figma-nodes.json) 包含 46 个状态画板及 `MomCozy/DiaryQuestion` 组件（309:1102）。

固定标题、分区切换和保存操作；日期、阶段、记录数量及引导语进入可滚动的浅色渐变卡。问题按卡片分组，可选问题保留折叠结构；选项使用 14 字号、薄荷选中底色和青色边框。同排按钮按最长文字统一高度，大字号根据可用宽度改为一列或两列。备注标题独立显示，避免窄屏大字号被输入框省略。输入、错误提示、按钮和确认弹窗复用妈妈页 Tokens、局部主题及公共组件。

生产改动仅涉及 `mother_diary_editor.dart`、`mother_diary_page.dart`、`diary_fields.dart`、`choice_field.dart`。选项组件新增 `momTiles` 和 `momSegmented`，旧 `warmTiles`／`warmSegmented`／`chips` 保持原样，宝宝表单没有迁移。控制器、模型、仓库、路由和保存协议均未改动。[行为对比](behavior-checks.json) 核对 19 个字段回调、互斥选择、清空不适部位时同步清空程度／影响、离开与保存方法以及旧选项渲染实现。

新增回归测试发现：快速完成的冲突载入可能跳过中间 loading 帧，导致 `TextFormField.initialValue` 仍显示旧备注。修复为仅在用户确认放弃后更新本地表单实例；取消确认仍保留草稿。测试先复现该问题，再验证服务器版本 8 的内容显示正确，后续保存使用版本 9，2000 字备注与其他字段保留。

验证结果：

- [144 项最终联测通过](joint-final-tests.log)，最终联测未更新图片基线。包括日记原有流程、新增冲突与备注边界测试、共用选项、妈妈首页与交接状态、导航、宝宝资料／记录表单及健康记录领域测试。
- [5 个文件静态分析通过](analyze-final.log)。[155 张验证图](verified-images.json) 逐组核对，覆盖 320／390／430 宽度、普通／双倍字号、三分区、条件与折叠字段、键盘遮挡、保存结果和失败反馈。
- 新增 12 个组合测试验证加载时禁用保存、读取失败重试、2000 字截断、冲突时草稿保留、确认重新载入、保存时禁用关闭／切换／重复保存、版本递增，以及三种快速心情预填、压力互斥选项、清空已保存记录后的空表单校验。
- [1308 个来源截图和元数据文件](source-image-hashes.json) 归档时指纹全部一致。没有写入 Session A 的截图目录、执行 inventory 截图测试、构建或部署。

[覆盖记录](coverage.json) 将来源状态映射到共用 Figma 状态族；同一表单的选中／取消／重新展开等组合复用设计，不意味着逐一重放全部 238 条原始截图序列。确认框与加载指示沿用 Flutter 自适应控件；Figma 表示布局和状态，日期、选中数量、备注内容等夹具可能不同。键盘使用组件测试的模拟遮挡，尚未进行这一批的真机键盘与发布验收。

AI 结果中的日记链接所指向的目标页面已完成，相关待办已更新。最终累计 33 个已实现并经过组件验证的页面／模块范围，观察到 2818 个截图状态，198 条增量状态仍待复核。新增截图继续进入队列，不以此批完成代表整个 App 完成。下一步优先核对已完成泌乳、媒体和信息采集页面的新截图，再处理尚未重构的宝宝与个人资料范围。Goal 保持 active。
