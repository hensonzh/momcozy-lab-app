# 智能体对话页 UI/UX 逻辑梳理

本文以旧 Web 版 `AgentHub` 为基准，约束 Flutter 版智能体对话页的核心 UI/UX 逻辑。

更细的可执行测试矩阵见 `docs/ui-parity/agent-hub-ui-ux-test-cases.md`。

## 核心布局

- 顶部控制区固定在聊天 viewport 上方，包含语音模式和新建会话。
- 聊天 viewport 独立滚动，底部输入栏固定在页面底部。
- 内容不足一屏时，对话内容应贴近输入栏上方，从底部向上排布。
- 内容超过一屏时，保持正常向上滚动，最新消息在列表尾部。
- 顶部保留轻量 fade，不遮挡消息主体。

## 消息流

- 新会话空态只显示默认问候语。
- 用户发送后必须立即插入用户气泡，并创建当前 assistant turn。
- 当前 assistant turn 在收到文本前显示“我已经收到你的消息啦～”这类状态文案，不能复用默认问候语。
- 网络失败、超时、断连时，当前 turn 显示失败文案和重试入口，不能把默认问候语染成错误态。
- 新发送 turn 必须锚定到最新位置，即使用户之前停留在历史位置。
- 流式回复期间，如果用户仍在最新位置，应持续跟随 tail；如果用户主动回看历史，后续应显示“回到最新消息”入口。

## 输入栏

- 单行输入态：文字、图片按钮、语音按钮、发送按钮垂直居中。
- 语音转写只回填输入框，不自动发送。
- 图片选择先暂存，发送时再作为本轮请求 payload。

## 交互状态

- 发送中禁用重复发送，发送按钮切换为停止/取消入口。
- 新建会话在运行中不可点击。
- 重试复用上一次请求，不重复插入用户气泡。
- 取消后保留已产生内容，并显示停止状态。
- 自动语音播放只在最终 assistant 文本完成后启动。
- 通知语音优先级高于普通自动回复语音。

## 当前 Flutter 覆盖

- `agent_hub_page_test.dart` 覆盖 composer 布局、图片、语音、发送、取消、重试、错误脱敏、工具进度、artifact、action、引用链接和长内容滚动。
- 已新增发送失败回归用例：发送后不显示默认问候语，并确保失败 turn 锚定在聊天 tail。
- 已统一 composer 三个按钮尺寸和中心线，并覆盖短输入态与展开态。

## 后续高风险项

- 历史窗口分页：旧 Web 一次只显示最新 N 条，并支持“查看更早对话”；Flutter 当前仍是完整 history 直接渲染。
- 流式 rich text 与 artifact 排序：旧 Web 明确要求最终文本优先于延迟 artifact。
- AG-UI action/card 交互：Flutter 已有基础渲染与确认测试，但还需逐类对齐旧 Web 的表单、媒体、IBCLC、hospital bag 等动作。
- 语音 avatar 动画：旧 Web 区分 greeting/thinking/speaking，Flutter 仍需继续对齐细节。
- 键盘弹出与 viewport 避让：需要补 emulator/integration 级验证。
