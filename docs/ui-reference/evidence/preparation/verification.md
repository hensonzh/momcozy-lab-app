## 当前实现

用户进入原生 room 路由后的准备内容改为居中、白色的预约详情容器：固定标题与关闭、紧凑预约信息、分隔线、绿色倒计时、准备说明和取消／开始两项操作。真实日期按预约时区格式化，保留时区缩写；不捏造首次咨询序号。当前代码没有重复的旧用户准备布局；保留下来的手动画面预览、大卡片和工作台操作仅在专家分支使用。

ProductFlowDialog 增加可选 alignment，默认仍为 bottomCenter；只有此准备页选择 center。长内容可滚动，320 大字号时两个按钮纵向排列，44 以上触控和关闭保持可达。准备组件每秒只刷新展示，不增加 API 轮询，也不自动调用进入。原有 RoomController 每五秒同步真实状态、服务器时间偏移和媒体生命周期不变。

取消使用已存在的 showAppointmentCancellation 和 AppointmentApiRepository；成功返回 Me，取消或失败返回后重读预约上下文。取消期间禁止其它操作。取消与入室请求参数、幂等、授权和核心后端逻辑没有改写。信息采集未完成仍提供真实入口；视频未开放、未到时间、进入时间已过各自禁用开始，过期提供既有重新预约入口。失败时保留刷新咨询状态。pendingEnd 未核对时不能开启新进入流程。

原生仍保留可由通知直接打开的独立路由；因此居中容器后方是原生页面背景，不伪造主页截图。设计的浏览器演示可随时进入不复制为真实环境规则：只有服务端明确允许提前进入且窗口有效，才标测试模式。模拟媒体会说明不传输远程音视频。地区支持由后续既有 API 核验，准备文案不写死 California。
