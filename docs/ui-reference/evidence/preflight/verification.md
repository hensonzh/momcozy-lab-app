## 参考与对应范围

重新查看当前设计 `src/pages/UserApp.tsx` 541–553 行 StartConsultModal、样式 795–808 / 2671–2677 行，以及旧 state-47/48/49/50。重新运行隔离的设计浏览器流程，捕获 `services/state-{47,48,49,50}-viewport.png`；捕获记录见 capture-manifest.json。设计浏览器阻断 API 和外部请求，以受控 getUserMedia 呈现设备通过，不代表真实咨询成功。

用户流程现在是“开始咨询 → 设备检测 → 继续确认 → 当前所在州 → 确认并进入咨询室”。位置确认使用统一底部弹窗，保留固定标题和关闭、紧凑说明、单独字段标签、下拉选择及一个主按钮；地区不支持或缺少视频授权时显示琥珀色说明。未授权入口连接单独的“本次服务的视频咨询授权”衍生设计。

state-47/48/49 仅验收此确认弹窗的可进入、地区受限和未授权状态。准备页背景、视频房间及全局隐私授权页并未因此完成。原设计 state-50 的“去授权”实际打开 PrivacyPage 五项全局设置，已纠正清单映射；它仍为 Need Review，不用仅处理 episode video scope 的弹窗冒充完整隐私管理。

## 业务保留与视觉差异

- 不把浏览器演示中“只有 CA 受支持”的条件移入 App。用户主动确认后由现有 checkLocation 接口判断；服务端拒绝才禁用继续，同样支持现有预约中的其它州。提示用户确认实际所在地或重新预约。
- 视频授权继续调用既有 grantVideoConsent，明确默认未勾选，仅写本次服务 video scope 和原有版本。接口只有当前布尔值，故文案为“需要开启…”，不推断从未授权的用户曾经撤回授权。
- 原生授权补齐采用已批准的衍生规范：标题、用途、同意复选框、确认按钮和请求失败。全局五项隐私设置继续单列。
- 保留原生至少 44 的触控区域；字号放大时标题、提示和按钮可换行，长内容在固定标题下滚动。正常字号结构与当前设计图对照。底层准备页及其遮罩背景未作为本次视觉完成范围。
