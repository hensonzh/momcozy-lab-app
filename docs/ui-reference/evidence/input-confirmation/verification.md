# 公共输入与丢弃确认

## 参考与范围

输入依据设计工程 `src/styles.css` 的表单规则、`src/styles/me-diary.css` 的暖色选项，以及生活陪伴型 Design System。原生日期和时间选择遵循统一主题与真实时区字段；日期/时间系统面板属于原生适配。丢弃确认没有独立稿件，已依据用户授权在 `common/derived/confirm.md` 标记为衍生设计，引用原稿 Modal 与公共规范。

本轮核对设计库快照与原设计工程 `styles.css`、`UI.tsx`、生活陪伴型规范一致。清单中的输入参考已由仅声明字体继承的 `input` 改为实际表单规则。

`MonthSelector` 的调用只存在于 IBCLC 日历，已移入工作台单独清单；未调整其实现。用户 App 的日期时间控件为 Baby 记录中的 `ZonedDateTimeField`。

## 改动与视觉检查

- 日记的重复丢弃弹窗改为调用 `confirmDiscard`，保留“放弃修改”文案。其它调用默认仍为“离开”，确认组件只返回选择，不保存或删除数据。
- 初次组件行为测试通过，但目视截图发现 320 宽、2x 字号时系统日历数字裁切，上午/下午文字裁切。问题截图保留为 `before-date-320-2x.png`、`before-time-320-2x.png`，没有将通过功能测试视为视觉验收。
- 大字号改为日期及时间输入模式，完整显示日期、小时、分钟；常规字号保留日历和钟面。时间按字段现有 24 小时展示格式选择，时区换算及夏令时歧义处理保持原逻辑。
- 选项继续使用现有三种样式。选择、取消选择、多选互斥均保留；暖色瓦片的选中边框和底色按日记专项规范复核。

## 验证证据

- `component.txt`：320/390/430 × 1x/2x 六组组件测试及一组短键盘视口测试，共七项。覆盖三种选项样式，时间禁用/清除，日期取消、时间取消，非法日期反馈，确认保留时区值，以及继续填写、系统返回、放弃和结果不确定说明。
- `regression.txt`：76 项检查通过，覆盖日记、Baby 资料和记录、个人日程、信息采集及共享输入；包含保存失败保留草稿、日期时区/夏令时、短键盘视口可到达恢复按钮。
- 金图位于 `test/goldens/design_system/input-*.png`，为组件状态截图，不充当完整业务页面原稿。

- `native.txt`：Android 1x/2x 组件交互通过，14 张 `native-input-*.png` 覆盖三种选项、日期、时间、确认和保存结果不确定。已目视核对完整日期、小时和分钟，以及确认文案和操作区域。原生组件夹具不访问业务 API。
- `keyboard.txt` 与 `input-*-keyboard-320-2x.png`：320×568、底部键盘占 280、2x 字号时可填写、取消、确认；日期面板自适应隐藏冗余头部，确认说明可滚动查看，底部动作可达。
- `analyze.txt`：六个变更文件静态检查无问题；`build.txt`、`install.txt`：普通 local APK 构建并覆盖安装成功。
