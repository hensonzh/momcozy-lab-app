# 图片、视频与 PDF：衍生设计验收

范围为用户 App 的 `/media-viewer`。依据 `common/derived/media.md`、`common/derived/pdf.md` 和公共设计系统；没有独立原始稿件，仍明确标记为“衍生设计”。专家工作台不在本次范围内。

## 实现

- 返回栏沿用暖色背景、细分隔线和 44 触控目标；长标题最多两行，辅助技术仍可读取完整标题。
- 图片、视频使用深色舞台；视频仅保留一组播放、进度、音量、全屏操作，底部考虑安全区域。
- PDF 保留真实文档比例和弱页间阴影，新增页码、前后翻页和缩放工具。两倍字号下工具分两行；首页/末页禁用对应翻页按钮。双击放大、拖动浏览保留。
- 切换图片或 PDF 时先显示加载状态，避免新标题下短暂出现旧资源。视频全屏播放中断时提供返回播放页入口，随后可重试。

## 验证范围

`test/features/media/` 覆盖图片加载/失败/重试/缩放、资源切换、401 刷新一次、403 和不支持的内容、PDF 加载失败及离开、视频初始化/播放/暂停/全屏/中断恢复。布局覆盖 320、390、430 宽度与 1x、2x 字号。

`test/native/media_pdf_design_test.dart` 使用本地 PDFium 和两页 PDF，核对正文实际绘制后再保存金图，并通过界面按钮验证页码边界、翻页、放大、缩小，以及拖动和双击缩放。PDF 控制器就绪并不代表文档已绘出，因此以正文内色条像素额外验证渲染完成。

Android 集成测试使用本地夹具：PDF 通过隔离的资源 connector 返回；视频通过设备回环 HTTP 服务播放已有 MP4，核对 Bearer 请求头。截图写入 App 私有目录后导出。返回目标使用隔离的页面，避免触发 Agent 网络请求。

这些测试验证原生 PDFium、原生视频解码和用户 App 的媒体界面，不代表线上资源服务或远程账号授权已完成端到端验收。最终执行结果与截图见同目录日志。

## 执行结果

- `regression.txt`：93 项通过，包含媒体仓库/组件、真实 PDFium、Agent 图片预览和路由约束。
- `analyze.txt`：无问题。
- `native-video.txt`：视频用例通过；同一次执行里的 PDF 校验因正文采样区域过窄失败，保留原始日志。
- `native-pdf.txt`：修正采样区域后，独立 PDF 用例通过。第一页和第二页截图均可见真实正文，翻页/缩放/返回正常。
- 实际查看了 Android 的普通视频、全屏视频、PDF 两页截图，以及 320/390 的图片加载成功、失败、PDF 正文/加载/失败和 2x 工具栏金图。标题、控件未遮挡正文，无可见布局溢出。

Android 视频、PDF 共 2 个用例分别通过；没有把首次组合执行中的失败计为通过。
