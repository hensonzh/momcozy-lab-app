## 设计依据与差异

重新读取设计工程 UserApp.tsx ServicesPage（3275 起）、ServiceDetailPage（3313 起，主体 3402–3415）及对应详情、目录组件，重新捕获 catalog-current 和 package-{feeding-confidence,better-breastfeeding,milk-supply-care,comfortable-feeding} 的 viewport 与完整滚动参考。浏览器仅使用本地设计工程，全部 API 和外部请求被阻断。

四类详情继续使用同一原生组件；各自名称、价格、说明、天数、咨询次数和交付列表来自实际 ServiceCatalog，不复制四个静态页面。团队头像没有 API 字段时沿用中性团队图标；不把设计演示人物当作实际可约专家。设计演示账号可能已购买部分方案，原生测试账号没有购买，其底部操作状态据真实订单和服务决定。已购方案仍保留查看我的服务入口，不复制演示的禁用按钮而使用户无法进入自己的服务。

本轮发现并修复：目录刷新失败时保留旧数据却没有反馈；无方案没有说明；继续付款异步读取订单时没有忙碌反馈；两倍字号下返回按钮文字受宽度挤压。目录增加刷新、错误重试和空状态；详情重载失败显示错误并暂时禁用购买，防止依赖旧订单信息继续；打开订单时显示正在打开并阻止重复操作，失败后恢复按钮。返回文字按设计缩小到 12 基础字号，并使用足够的内边距与宽度。
