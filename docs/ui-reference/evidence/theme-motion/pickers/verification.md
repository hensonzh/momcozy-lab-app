# 日期与时间选择器复核

重新阅读生活陪伴型 Design System、输入控件参考和既有输入确认验证记录。日期/时间弹窗没有独立设计稿，按统一规范补为衍生设计，详见 [输入规范](../../../common/derived/input.md)。

## 实现与行为

- 10 个用户 App / 共用文件的 12 个日期、时间入口统一使用 `showMomCozyDatePicker` 和 `showMomCozyTimePicker`。调用方继续提供原有日期范围与时间值，时区转换、提交和保存条件不变。
- 普通字号保留 SDK 日历和钟面；日期保留 DatePickerTheme 的本地化覆盖，时间保留调用方的 24 小时格式设置。减少动态效果时，弹窗的打开和关闭使用零时长。用户主动翻月/拨盘仍由平台控件处理，本轮没有替换 SDK 内部交互。
- 大字号日期沿用输入模式。复核发现 SDK 时间输入弹窗在 320×568、2 倍字号的英文界面发生 35px 纵向溢出，校验后确认按钮无法点击。因此大字号时间改用可滚动的统一 AlertDialog：小时、分钟纵向排列，按本地化保留上午/下午或 24 小时制；确认使用主按钮。无固定内容高度，不压缩用户字号。
- 新时间弹窗只在确认有效值后返回 TimeOfDay。取消或系统返回为 null，午夜/中午转换、分钟范围和小时范围均由测试覆盖。

## 验证

- `before.txt`：原日期弹窗在两个无耗时帧后仍未完成，复现减少动态效果遗漏。
- `component.txt`：11 项通过，包括日期边界、本地化覆盖、错误时间、12 小时午夜/中午、无耗时打开，以及 320/390/430 × 1x/2x 和短屏键盘场景。截图更新后另由完整回归校验。
- `regression.txt`：833 项通过，覆盖共享控件、首次使用、Agent 表单、Baby、妈妈、日程、服务。普通字号的既有视觉结果保持一致；大字号时间的新正常/错误/滚动截图位于 `test/goldens/design_system/input-time-*.png`。
- 大字号键盘场景不仅检查控件存在，还实际滚动并编辑分钟字段、点击取消/确认；日期或时间取消不会触发记录变更。
- `native.txt`：Android 1x/2x 的实际组件选择、日期/时间取消与确认、错误恢复、分钟编辑均通过。首帧状态检查使用两个无耗时帧，截图在布局完成后采集。已目视检查日期、时间及错误提示完整可读，操作按钮可见；保存六张日期/时间原生截图。
- `analyze.txt`：共享实现与相关测试静态检查无问题。
- `build.txt`、`install.txt`：普通 local APK 构建并覆盖安装成功；已替换原生测试入口并恢复 Mia 登录首页，见 `native-restored-home.png` 和对应 XML。

本轮没有调用保存记录的真实 API。公共 Theme 的字体及覆盖关系仍需继续复核。
