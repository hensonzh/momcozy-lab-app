# 公共加载、空状态、错误与保存反馈

依据 `common/derived/loading.md`、`common/derived/error.md`、`common/derived/success.md` 及设计工程 `src/components/UI.tsx` 的 `EmptyState`。已核对参考库中的 `UI.tsx` 与原设计工程文件一致。加载、错误、保存反馈为用户认可的衍生设计；空状态保留原设计组件来源。

## 实现与映射

- `ProductLoadingView` 新增单一无障碍加载说明和 live region；未传 label 时播报“正在载入”。短高度区域可滚动，不再因 2x 字号产生 RenderFlex 溢出。常规区域的配色、间距和位置保留。
- `ProductEmptyView` 新增可选起始侧对齐；记录列表、信息采集和服务进度按设计稿沿同一侧排布标题、说明和入口。媒体、工作台等既有调用保持默认行为。
- 错误组件沿用就近提示与明确恢复操作，区分离线、登录过期、无权限、数据冲突、校验失败和暂不可用；冲突使用“重新载入”。保留草稿的页面显示对应说明。没有把失败统一当成空数据。
- 保存和撤销的实际实现是 Baby 的 `BabySavedFeedbackView`、泌乳记录的反馈区及主题中的 snackbar，而非原映射指向的 `product_feedback.dart`；清单已改为真实文件并补充关联实现。保存结果仍显示在内容区，撤销忙碌时禁用重复操作；不可确认/不可撤销分别进入现有恢复和核对流程。

## 功能证据

- `before.txt` 复现加载无标签和短区域溢出；`component.txt` 证明修复后通过，覆盖三种宽度和 1x/2x、空状态入口、六类错误回调，以及无障碍 live region。
- `regression.txt`：304 项相关回归通过，包含公共组件、服务、首次使用、Baby 保存撤销、泌乳状态。服务目录刷新失败仍保留已有内容；忙碌操作阻止重复提交；保存失败保留有效输入。
- `alignment.txt`：新增起始侧对齐后，47 项组件、Baby 记录、信息采集、服务进度检查通过。
- `native.txt`：Android 公共组件夹具在 1x/2x 下展示加载、错误、空状态、保存、已撤销，并验证重试/撤销/关闭回调。该夹具只在内存中演示组件状态，不调用保存、删除或外部服务。

实际功能流程另有当前仓库证据：`evidence/baby-feedback/` 的保存/已撤销截图，`evidence/milk-states/` 的保存/删除/撤销截图与交互记录。此次再次运行对应回归：批量撤销只重试未确认记录、忙碌锁定、宝宝切换、版本冲突和不可撤销既有记录；不把夹具的回调成功当作真实 API 成功。

## 视觉范围

已目视核对 Android 1x/2x 的加载、错误、空状态、保存与已撤销，以及 320/390/430 金图。暖色底、提示层级、动作与内容间距一致；错误和保存反馈没有通过弹层遮挡主操作。大字号内容可换行，短加载区域可滚动。真实页面中的空记录状态另存原生截图。

普通 local APK 构建、安装成功。真实本地账号从 Baby → 查看全部记录，确认喂养与尿便两个分类为空，标题、说明和“去记录”沿同一侧排列；从尿便空状态点击“去记录”打开正确的换尿布编辑器。未填写或保存，关闭后返回首页。见 `native-records-empty.png`、`native-records-diaper-empty.png` 和 `native-empty-action.png`。
