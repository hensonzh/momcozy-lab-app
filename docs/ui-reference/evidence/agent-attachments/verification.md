# Agent 附件菜单与文件附件预览

## 设计依据

重新阅读设计工程 `UserApp.tsx` 的 AgentPage / AgentMessageAttachments，以及 `styles.css` 的附件菜单、待发送附件和消息附件规则、后加载的 `me-agent.css`。后者与参考库副本 SHA256 一致。对照 `agent/reference/attachments.png`：输入栏上方的轻量菜单、三种来源、紫色线图标与淡紫圆底、标题和辅助说明。

## 已修正的差异

- 菜单恢复两级信息、40 图标底、22 线图标、52 最小行高、20 圆角和 6 内边距。相机、图片、文件路径来自设计工程 UI.Icon，纳入现有线图标组件。菜单上移，避免覆盖输入按钮；大字号适度扩宽并允许说明换行。
- 打开附件菜单先释放输入焦点，收起键盘并保留草稿。测试从已聚焦的输入框打开菜单，核对焦点、位置与后续选择/移除；没有在菜单关闭时自动重新弹出键盘。
- Android 复核发现大字号时仅依附加号仍会覆盖展开的草稿，现改为整个输入表面作为锚点；测试直接断言菜单底部在输入表面上方。点击输入文字会关闭菜单并继续编辑，草稿不丢失。
- 待发送图片与文件使用同一附件组件，在一条横向滚动区域排列，取消原先图片/文件各一行的计数栏。图片显示 42 缩略图及真实文件名、大小；文件使用对应图标。卡片 14 圆角、6 内边距、最长 218 宽，小屏按可用宽度缩放。
- 移除按钮由 24/28 扩大到 44 触控尺寸，上传或清理中仍禁用。文件名超长可省略，但保留完整 tooltip 和文本语义。移除、上传、请求和缓存恢复仍调用既有逻辑。
- 已发送文件按原稿呈现 20 图标、11 文件名、9 大小、11 圆角、7/8 内边距、6 项间距。原清单误将 AgentMessageAttachments 标为 dialog，现纠正为消息内文件附件组件；没有把它当成独立 PDF 阅读器。

## 契约差异

设计菜单写有 Word、表格等，但当前原生 `AgentHubPlatformDocumentPicker` 仅选择并校验 PDF，最大 10 MiB。本轮显示“PDF · 最大 10 MB”，没有扩大底层上传能力或制造不可用入口。图片沿用原生选择器。单次附件上限、上传后的文件 ID、移除失败保留草稿等业务规则未改变。

## 验证

`before.txt` 复现菜单缺少辅助说明。新组件场景覆盖 320/390/430 × 1x/2x 的短屏、菜单定位、图片与文件同排、横向滚动、44 移除目标、上传禁用、移除后保留文本，以及字节/KB/MB 文件大小；截图为实际 Flutter 渲染。

`regression.txt`：399 项正常模式回归通过，未启用更新金图。包含原有完整 AgentHubPage 的上传、图片/文件请求、草稿恢复、上传清理与失败恢复、限制、流式状态，以及公共组件。三处旧计数文字断言改为核对实际附件文件名，原上传/请求断言仍保留。

Android 测试使用本地内存附件与回调，只验证 UI、文件元信息及草稿操作，不发送 Agent 消息，也不调用真实上传或删除 API。真实菜单的本地 App 检查单独记录；不能将组件回调当作模型处理成功。

最终 `native.txt` 在 Android 1x/2x 通过，包含聚焦输入后打开菜单、返回编辑、再次打开并选择来源、附件滚动和禁用移除、移除后草稿保留。十张截图覆盖菜单、待发送图片/文件、上传中和已发送文件元信息；已目视确认菜单位于整个输入表面上方。`analyze.txt` 对八个相关实现和测试文件静态检查无问题。截图中的文件均为测试夹具。

普通 local APK 构建、覆盖安装成功，见 `build.txt` / `install.txt`。从真实本地账号进入 Cozymate，打开“添加附件”，`native-app-menu.png` 和 XML 确认相机/照片/PDF 三项及格式说明、紫色线图标和菜单位置正确。没有选择真实文件、拍照或发送消息。首页问候与历史能力的既有限制归在 agent/home，未因附件菜单验收而标为完成。

检查后关闭菜单并返回 Me，`native-restored-home.png` / XML 确认 Mia 首页恢复。清单将附件菜单与文件附件预览两项标记 Completed：147 总项、130 Completed、17 Need Review、0 Missing Reference；104 个用户 UI 文件均有映射。其余 Agent 状态、隐私/服务契约和局部 Theme 审计仍保持待复核。
