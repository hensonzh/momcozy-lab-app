# 对话图片与全屏预览

## 参考与边界

重新阅读设计工程 `UserApp.tsx` 的 AgentMessageAttachments 与 `styles.css` 的消息附件元信息规则。原稿没有原生全屏图片的独立页面，因此按用户授权建立 `agent/derived/image-preview.md`：元信息行沿用原稿，保留已支持的鉴权缩略图；全屏部分继承已确认的公共媒体规范。清单明确标为衍生设计，不把新截图称为设计工程原稿。

## 修改

- 消息图片由裸缩略图网格改为带缩略图、文件名和大小的可点击元信息行，复用文件附件排版。11 文件名、9 大小、11 圆角、7/8 内边距、6 行间距；20 缩略图保留原生辨认图片的能力。整行最小触控高度 44，长文件名保持完整文本语义及 tooltip。
- 全屏图片复用从现有媒体页面提取的 `MediaViewerHeader`、`MediaViewerLoading` 和 `MediaViewerLoadError`。暖色标题栏始终可返回，深色舞台只在实际图片加载后提供平移与缩放。公共媒体原有布局和按钮键未改变。
- 空响应不再无限等待；同步异常、异步拒绝和图片解码错误进入明确失败态。有鉴权原图读取器时可重试，本地缓存损坏也可重新请求原图；没有来源时提示返回重选，不提供无效重试。
- 读取器仍通过现有 fileId 和注入仓储访问图片，不增加公开 URL 或绕过鉴权。缩略图与原图分别读取；取消预览后完成或失败的请求不会重新打开页面。
- 移除已无调用的旧“点击查看”分支；未知大小显示“大小未知”。历史模型的缺省 0 不再呈现为真实空文件。

## 验证方法

`before.txt` 复现消息中缺少文件名。针对性测试使用仓库中可真实解码的 milk-hero 图片，分别等待原图与缩略图解码后截图；旧的极小 base64 测试数据未能通过当前解码器，已替换，避免仅看到 Image widget 就认定加载成功。

320/390/430 × 1x/2x、568 短屏覆盖元信息、加载、空响应、重试成功、双指缩放、系统返回及本地损坏且无远程来源。额外检查同步/异步读取失败、损坏远程数据、损坏本地数据后回源恢复、关闭后迟到失败，以及鉴权读取的 ID 和次数。

Android 使用同一生产组件与内存读取器验证实际渲染，不上传文件、不发送消息。此证据不代表模型识图或远程服务可用。消息操作菜单另列待实现/复核，不因图片预览完成而改变状态。

## 最终结果

- `regression.txt`：494 项 Agent、媒体、流式事件和共享组件回归通过，包括 36 张图片状态金图；原有公共媒体金图保持通过。
- `analyze.txt`：9 个相关文件静态检查无问题。
- `thumbnail-before.txt`：空缩略图持续加载的失败用例；最终回归已验证空响应停止加载，并且仍可打开原图。
- `native.txt`：Android 集成测试通过，1x/2x 下共 12 张实际截图。已目视核对元信息缩略图、完整图片、长标题与失败提示；大字号换行正常，返回始终可用。
- 共享媒体标题和反馈组件仅从原实现提取复用；本轮媒体回归覆盖原有图片、视频和 PDF 行为，未新增服务端接口。
- `build.txt`、`install.txt`：普通本地 Debug APK 构建并覆盖安装成功，已退出集成测试宿主；`native-restored-home.png/xml` 确认恢复已登录的 Mia 首页。修改尚未提交。
