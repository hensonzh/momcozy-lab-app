2026-09-12，本轮只涉及用户 App。独立 IBCLC 工作台保持清单范围。信息采集已有原始设计，不标为衍生设计；缺少独立原稿的其他页面继续采用已批准的统一规范，并在清单明确标注“衍生设计”。

## 设计与实现

重新核对当前 `src/pages/UserApp.tsx` 中 IntakePage（3453–3540 行）、styles.css 的 intake 规则及原始 state-39–42。通过隔离的设计浏览器建立新预约后采集当前状态：`services/state-{39,40,41,42}-viewport.png`、`services/intake-saved-viewport.png`。截图阻断所有 API 和外部请求，仅使用设计工程演示数据，来源登记在 capture-manifest.json。

- 紧凑返回/居中标题与下分隔线；正文统一 16 边距、14 分组间距。核心卡片包含三列问题选择、两行目标输入和可折叠的补充情况。
- 基础信息改为独立折叠区，显示预填/待完善状态；常规屏宽双列，窄屏或大字号单列。保留真实宝宝 ID、出生日期、出生记录性别、喂养枚举及多宝宝选择。月龄按设计的日/周/自然月规则推导，仅用于显示；API 不引入演示稿的年龄字符串或风险字段。
- 信息使用采用锁图标、说明入口、分隔线和明确勾选。说明弹窗展示提供给谁、包含什么、用于什么，沿用共享的底部弹窗。仅保存既有 ibclcCase 授权，不复制设计演示代码中额外的视频或全局授权。
- 必填条件与授权未完成时保存按钮禁用；保存结果不确定时仍允许重试原快照，输入锁定，避免产生内容不同的重复提交。
- 首次保存成功展示完成弹窗、实际预约日期/时间/时区、实际专家姓名以及预问诊/查看预约入口。已有表单修改后直接返回预约，不重复展示首次引导。无真实头像 URL 时显示专家姓名缩写，不使用设计稿演示人物头像。
- 预约与信息采集共用 ServiceFlowTheme；ProductFlowDialog 增加默认开启的 showClose 参数，本次完成弹窗隐藏关闭按钮，保留两个明确去向。
