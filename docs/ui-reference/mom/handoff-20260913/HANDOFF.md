# 妈妈首页 Flutter 开发智能体交接文档

> 本文档是可直接交给 App 端开发智能体执行的任务说明。执行时请同时提供 `mom_home_flutter_handoff_final.zip`。

## 1. 你的角色

你是一名负责现有 Flutter App 的高级客户端工程师。请将交付包中的“妈妈首页”接入当前 App，使实际运行页面与 Figma 设计保持一致。

本任务是**已有 UI 的工程化落地**，不是重新进行产品设计或视觉设计。除适配现有项目架构外，不要擅自改变模块顺序、文案、颜色、间距、圆角、状态逻辑或交互入口。

## 2. 交付目标

完成妈妈首页的 Flutter 开发，覆盖以下三种页面状态：

1. **初始态**：用户尚未完成今日记录，且未购买专家服务包。
2. **有数据态**：用户已产生泌乳、身体、休息和心情数据，但未购买专家服务包。
3. **已购服务态**：用户已有当日数据，并购买了正在进行的专家陪伴服务包。

最终页面需要接入现有 App 的路由、状态管理、接口数据、埋点与底部导航，不能停留在静态 Demo。

## 4. 开发前必须完成的检查

在修改代码前，先检查现有项目并输出简短结论：

1. Flutter 与 Dart 版本。
2. 当前路由方案，例如 GoRouter、Navigator 2.0 或项目自研路由。
3. 当前状态管理方案，例如 Riverpod、BLoC、Provider、GetX 或项目自研方案。
4. 现有 Design System：颜色、字体、按钮、卡片、底部导航、间距 Tokens。
5. 是否已有妈妈首页、泌乳记录、恢复状态、专家服务相关页面或组件。
6. 当前接口层、Repository、DTO 与错误处理方式。
7. 当前资源目录与图片 CDN 使用规范。

优先复用现有组件、Tokens、路由和状态管理方式。不要为了接入本模块再引入一套新的架构或重复组件。

## 5. 页面信息结构

页面模块顺序必须保持如下：

```text
问候与产后阶段
↓
AI 每日分析
↓
今日泌乳
↓
今日状态
  ├── 身体与精力
  ├── 昨夜休息
  └── 今日心情
↓
专家陪伴计划
↓（仅已购买时显示）
我的陪伴计划
  └── 进行中的服务包
↓
App 现有底部导航
```

不要把“今日泌乳”合并到“今日状态”中；两者是不同层级。不要把“专家陪伴计划”替换为“我的陪伴计划”：已购状态下两个模块需要同时存在，前者是服务总入口，后者管理用户已购买的服务。

## 6. 状态与展示逻辑

推荐将页面状态拆成业务维度，而不是只依赖一个枚举：

```dart
class MomHomeViewData {
  final bool hasTodayRecords;
  final ActiveCompanionPlan? activePlan;
  final AiInsight insight;
  final LactationSummary lactation;
  final RecoverySummary recovery;
}
```

交付包中的 `MomHomeViewState` 可用于 Demo 或页面预览；正式接入时应由真实业务数据推导 UI：

| 条件 | 页面表现 |
| --- | --- |
| `hasTodayRecords == false` | AI 等待首次记录；泌乳、身体、休息显示待记录；心情显示快捷选项 |
| `hasTodayRecords == true` | AI 展示每日分析；泌乳和恢复模块展示最新数据 |
| `activePlan == null` | 只展示“专家陪伴计划”入口 |
| `activePlan != null` | 保留专家入口，并新增“我的陪伴计划”和进行中服务卡 |

“有数据”和“已购服务”不是互斥业务概念。不要在后端模型中将它们设计成一个不可扩展的单枚举。

## 7. 建议的数据字段映射

### 7.1 页面头部

| UI 字段 | 建议数据来源 |
| --- | --- |
| `下午好，Mia` | 当前时段 + 用户昵称 |
| `产后第 21 天` | 分娩日期与当前日期计算 |
| `恢复建立期` | 产后阶段规则配置 |

### 7.2 AI 每日分析

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `eyebrow` | `String` | 数据来源或生成状态 |
| `title` | `String` | 当日最重要结论，最多两行 |
| `body` | `String` | 简短解释和行动方向 |
| `generatedAt` | `DateTime?` | 分析生成时间 |
| `detailId` | `String?` | 跳转详情使用 |

若没有足够数据，不要伪造分析结果，展示“等待首次记录”状态。

### 7.3 今日泌乳

至少支持：今日累计奶量、泵奶次数、亲喂次数、是否已记录。点击主按钮进入新增泌乳记录；点击“查看趋势”进入奶量趋势页。

### 7.4 今日状态

至少支持：身体/精力状态、明显不适、昨夜休息时长、与前一晚对比、今日心情。初始态的记录入口应保持低操作成本。

### 7.5 专家陪伴服务

建议接口模型：

```dart
class ActiveCompanionPlan {
  final String id;
  final String name;
  final String status;
  final String expertId;
  final String expertName;
  final String expertCredential;
  final String expertAvatarUrl;
  final int supportDaysRemaining;
  final int consultationsRemaining;
  final bool canBookConsultation;
}
```

当前设计示例为：

- 服务包：奶量管理
- 状态：服务进行中
- 专家：Jamie Lee
- 资质：IBCLC
- 支持周期：14 天
- 剩余咨询：3 次

正式开发时不得将这些示例数据硬编码为真实业务数据。

## 8. 交互映射

| UI 入口 | 必须实现的行为 |
| --- | --- |
| AI 建议卡 | 进入当日分析详情或打开智能体上下文 |
| `记录一次泌乳` | 进入泌乳记录流程，成功后刷新首页数据 |
| `查看趋势` | 进入奶量或恢复趋势页 |
| 初始态身体/休息/心情 | 打开对应的快速记录流程 |
| 专家陪伴计划入口 | 进入服务包列表或服务介绍页 |
| 服务进度 | 进入当前服务详情与时间线 |
| 预约咨询 | 进入预约流程；需根据剩余次数和服务状态控制可用性 |
| 底部导航 | 使用 App 现有导航逻辑，不在页面内创建第二套导航状态 |

所有点击事件需要接入现有埋点规范。推荐事件名可参考交付包中的 `DESIGN_SPEC.md`。

## 9. 视觉实现要求

- 页面基础宽度参考 393 px，但实现必须响应式，不得把整个页面锁死为 393 px。
- 页面左右边距 16 px，主要模块垂直间距 14 px。
- 页面背景为暖米白 `#FBF8F4`。
- 字体以 Noto Sans SC 为基准；如果项目已有统一字体，优先使用项目字体并进行视觉回归。
- AI 卡使用柔和粉色到淡紫色渐变，右上角保留 Cozymate 头像。
- 泌乳模块使用浅粉背景，主记录按钮使用品牌玫红色。
- 身体和休息采用低饱和暖米色；心情采用浅粉色。
- 专家模块以暖白为主，薄荷绿仅用于专家和服务状态，不能扩大为大面积冷色背景。
- 已购服务卡使用单个 IBCLC 头像，不得恢复为专家组头像。
- 点击区域不得小于 44 × 44 dp，文字缩放后不能被裁切。
- 页面内容可滚动；底部导航按当前 App 的真实导航结构固定展示。

## 12. 必须补充的工程状态

交付包提供了三种核心业务状态，但正式开发还必须处理：

- 首屏 Loading：优先使用骨架屏，避免所有卡片同时跳动。
- 局部接口失败：单个模块失败不得阻塞整个首页。
- 部分数据：例如有泌乳记录但没有心情记录。
- AI 分析生成中：显示明确的生成状态，不展示虚假结论。
- 服务已过期、已暂停、次数为 0、暂不可预约。
- 网络图片加载中和加载失败。
- 用户未设置分娩日期时的阶段文案兜底。

这些状态应复用现有卡片结构，不要另起一套视觉风格。
