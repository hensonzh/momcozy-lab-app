# 泌乳场景：用户问题、观察指标与按需记录

日期：2026-09-16。状态：产品方案草案；未修改 App、Figma 或后端。

后续方向已更新：以[《通用指标 + 按需专有指标产品方案》](postpartum-common-and-specific-recording-prd-20260916.md)为当前首页与展示规则依据。本文保留泌乳问题—指标映射供复用；通用的身体、休息、心情和适用的喂养记录明确常驻，不再仅在选择某个问题后才提供。

依据：用户提供的 12 类 IBCLC 咨询场景、当前 App 数据模型，以及 CDC、AAP、ABM、FDA 的相关资料。原图的需求强度用于初始产品优先级，不等于已验证的发生率、咨询占比或临床严重程度。下文中的字段、展示规则和产品优先级是设计建议，不能直接作为诊断或治疗规则。

## 1. 产品组织原则

采用「当前困扰/目标 → 需要了解的事实 → 最小记录集合 → 有依据的反馈 → 下次复评」组织体验。同一用户可以同时关注多个问题；展示时合并重复记录请求。

问题标签使用用户语言，如“喂奶疼”“担心宝宝没吃够”，不要求用户自行确认“低奶量”“乳腺炎”或“舌系带异常”。后者属于专业评估结果。

每项记录都必须说明用途、记录时机、数据来源、什么情况下不用再记，以及记录后能得到什么。具备记录能力不代表默认要求所有用户每天记录。

## 2. 问题—指标映射

“首轮”是启动该问题所需的信息集合，不意味着必须在一张表里全部填完。已有有效数据直接复用；未知、未观察与明确没有必须分开。

| 用户问题类型 | 首轮需要了解 | 按问题展开的补充观察 | 记录时机与回报 |
|---|---|---|---|
| 1. 含不住、容易掉乳、喂得费劲 | 哪一侧/何种喂法；是否能含住；是否反复脱落；能否观察到吞咽；妈妈是否疼 | 姿势、点击声/漏奶、喂后乳头形态、疼痛变化；专业观察结果 | 困难发生时记录一例，调整后对比；帮助专家明确哪一步仍困难。不要要求每次计数吞咽或自行打“含乳深度分”。 |
| 2. 喂奶疼、乳头破损 | 部位和左右侧；开始时间；发生于含乳、泵奶、喂后还是持续；疼痛程度及是否影响喂养 | 破损/出血/颜色变化；采取了什么措施及随后变化；有关泵具设置 | 发作或明显变化时补充；展示同部位前后变化，减少咨询时反复描述。疼痛量表如采用 0–10，属于主观报告，不作为单独诊断依据。 |
| 3. 担心没吃够、体重长得慢 | 宝宝日龄/早产背景；喂养方式；近期喂养、尿便；有日期的体重及出生体重（适用时） | 吞咽观察、瓶喂实际摄入、补充喂养、精神/唤醒与喂养表现；专业测量和评估 | 需要评估时组织一个明确时间窗内的已有记录，缺口再补；体重沿用实际测量或专业复评安排，不默认每日称重。反馈说明证据与缺口，避免直接输出“吃饱分数”。 |
| 4. 感觉奶少、想增加奶量 | 用户目标；当前亲喂/泵奶/混合方式；近期时间和次数；已测泵奶量；补充喂养；宝宝摄入相关观察 | 泵奶时长、间隔、设备/模式变化、漏记情况、疼痛；专业建议及执行结果 | 有限观察期内比较条件相近的记录；区分泵出量变化、喂养方式变化和记录完整性。不能用单次泵量确认低供给。 |
| 5. 涨、局部硬痛、担心乳腺炎 | 左右侧和位置；出现时间；红/肿/痛是否变化；已测体温、寒战/全身不适；最近喂养/泵奶变化 | 症状范围与趋势；额外排乳/按摩等已采取措施；是否就诊及现有医嘱 | 先处理需要专业帮助的情况，再做变化随访；界面不要求用户等待积累足够数据才求助，不把“排空量”“硬块揉散”设计成任务。 |
| 6. 拒乳、吃得困难、拒奶瓶 | 从何时开始；拒绝乳房、奶瓶还是两者；哪一侧；最近成功进食；当前摄入与尿湿信息 | 喂养者、环境、姿势、奶嘴型号/流速、接受/拒绝/部分接受、相关不适 | 选择代表性尝试记录，比较不同情境；不要让尝试次数成为必须达成的目标。完全不能进食等情况优先转专业帮助。 |
| 7. 吸乳器不舒服、泵奶效率问题 | 设备型号；左右侧罩杯型号/尺寸；模式/档位；泵奶时长；测量量；舒适度 | 摩擦/疼痛/肿胀、漏气、配件状态、前次喂养/泵奶间隔、设置变更 | 第一次和设置变化时记录设备信息，后续复用；对比同设备相近条件下的量与舒适度。不要跨品牌比较档位高低或把 ml/min 当统一效率评分。 |
| 8. 返工、储奶和交接安排 | 返工日期；离家时段；可用泵奶时间；现有喂养方式；照护者喂养需求 | 工作日实际泵奶、宝宝瓶喂实际摄入、储奶批次与入库/取用、奶瓶接受情况 | 返工前建计划，试行及返工后按需要复评；反馈可执行的时间安排与已登记库存，不设统一囤奶目标。 |
| 9. 奶多、喷乳、反复涨或呛 | 不适和发生情境；额外泵奶情况；宝宝喂养时表现；近期方式变化 | 漏奶/喷乳、喂养中断、体重资料、专业评估和已有减量安排 | 按症状和已有方案追踪，不把奶量越高定义为越好；App 不凭奶量自动确诊过量或下发减量治疗。 |
| 10. 担心舌系带/口腔功能 | 持续的含乳困难、疼痛、喂养表现、体重资料；已经做过哪些评估 | 专业人员的功能评估、建议与后续结果 | 作为含乳/摄入困难后的专业评估分支；不让家长自行打解剖分数，不用照片自动决定是否需要手术。 |
| 11. 想断奶、减少泵奶 | 用户希望减少到什么程度；当前喂养/泵奶模式；宝宝年龄及替代喂养情况 | 每次调整后的舒适度、局部症状、宝宝接受情况、专业计划 | 围绕已选计划的调整点复评；目标由用户决定，不设置固定“几天断完”倒计时。 |
| 12. 停奶后恢复、分离/旅行等特殊阶段 | 中断时长和原因；当前喂养与泵奶情况；宝宝摄入保障；现实时间条件及目标 | 恢复尝试、已测量变化、补充喂养、体重资料、专家跟进 | 以个人方案为单位分阶段复评；不承诺恢复时限，不根据泵量上升自动提示减少补充喂养。 |

第 1、3 类选择吞咽、喂养、尿便和体重等信息，参考 [CDC 新生儿哺乳观察](https://www.cdc.gov/infant-toddler-nutrition/breastfeeding/newborn-basics.html) 与 [AAP 出生后 3–5 天评估](https://www.aap.org/en/patient-care/newborn-infant-and-early-childhood-nutrition/newborn-and-infant-health-assessment-and-promotion/first-office-visit-3-5-days/)。这些资料的年龄范围有限，不能将新生儿阈值直接用于所有月龄。

第 5 类应区分用户观察与临床诊断；炎症相关问题不应被产品引导为反复排空或用力按摩任务，参考 [ABM 乳腺炎谱系指南](https://abm.memberclicks.net/assets/DOCUMENTS/PROTOCOLS/36-mitchell-et-al-2022-academy-of-breastfeeding-medicine-clinical-protocol-36-the-mastitis-spectrum-revised-2022.pdf)。第 9 类的干预需要个体化评估，参考 [ABM 泌乳过多指南](https://www.bfmed.org/assets/32%20Management%20of%20Hyperlactation.pdf)。第 10 类应以功能与喂养评估为中心，参考 [AAP 舌系带诊疗说明](https://www.healthychildren.org/English/news/Pages/AAP-report-addresses-rise-in-tongue-tie-diagnoses-for-breastfeeding-concerns.aspx)。

第 7 类围绕设备使用和舒适度的设计参考 [FDA 吸乳器使用说明](https://www.fda.gov/medical-devices/breast-pumps/using-breast-pump)；设备具体操作仍需对应厂商说明。第 8、11、12 类分别参考 [CDC 返工准备](https://www.cdc.gov/breastfeeding/features/returning-to-work-and-breastfeeding.html)、[CDC 断奶](https://www.cdc.gov/infant-toddler-nutrition/breastfeeding/weaning.html)、[CDC 恢复泌乳](https://www.cdc.gov/breastfeeding-special-circumstances/hcp/relactation/index.html)。表中的记录频率与交互方式是产品提议，并非上述机构规定的用户打卡任务。

## 3. 可复用指标库

| 记录组 | 字段建议 | 类型/单位与填写方式 | 展示条件 |
|---|---|---|---|
| 母婴背景 | 宝宝、出生日、孕周/是否早产、喂养方式；产后阶段、用户目标、已有专业计划 | 一次建档，变化时确认；日龄自动计算；未知可保留 | 启用相关问题时仅补缺失背景 |
| 亲喂事件 | 时间、宝宝、左右侧/双侧、可选时长 | 时间/分钟；计时器可选；不填“估计喝了多少 ml” | 关注亲喂过程或摄入情况 |
| 含乳与吞咽观察 | 含住情况、反复掉乳、是否观察到吞咽、点击声、喂后乳头变化 | 有/无/不确定或短选项；选择代表性事件 | 含乳困难、疼痛或专业观察要求 |
| 泵奶事件 | 一次 session、时间、左右侧、单侧量或双侧总量、时长、舒适度 | ml、分钟；单侧与合计模式互斥，避免累加两遍；0 与未知分开 | 用户实际泵奶且问题需要这些信息 |
| 瓶喂/补充事件 | 宝宝、时间、奶源、实际摄入、可选提供量与剩余量 | ml；明确实际摄入和配制/提供量的区别；允许未知 | 关注摄入、返工交接或既有补充喂养方案 |
| 尿便事件 | 时间、尿湿/便便/两者、必要时便色与异常观察 | 事件记录，由系统按时间窗汇总；未记录不能解释为零次 | 关注摄入或已有专业观察计划 |
| 体重测量 | 宝宝、测量日期/时间、体重、来源/测量条件；出生体重按需 | kg/g；复用就诊或家庭实际测量；可标记不同秤 | 关注增长或约定复评；不设普遍每日必填 |
| 乳房/乳头症状 | 侧别、部位、起始时间、发生阶段、疼痛程度、影响、红肿破损、变化 | 自报选项；必要时数值量表；疼痛程度不自动等于疾病严重度 | 有症状时启用 |
| 全身状态 | 已测体温、测量时间与方式、寒战/全身不适等 | ℃/℉及自报；没测就是未知 | 症状触发时询问，不默认每天测体温 |
| 设备档案 | 品牌/型号、左右罩杯尺寸、模式/档位、配件状态 | 设备信息复用；左右差异可保留；档位必须带设备上下文 | 泵奶问题或设备/设置有变化 |
| 情境与尝试 | 姿势、喂养者、环境、奶嘴/流速、尝试内容、接受情况 | 预设选项加可选备注；不要求穷举 | 拒乳、拒瓶、含乳困难 |
| 计划与反馈 | 谁提出的计划、版本、开始/复评日期、实际执行、感受/症状变化、求助结果 | 专家建议与用户自选目标分别标记；不从相关性推断治疗因果 | 当前有进行中的观察/支持计划 |
| 储奶与工作安排 | 时间窗口、场所条件、储奶批次/量/状态、交接与取用 | 日历和库存事件；安全储存规则单独维护 | 返工、分离或主动启用储奶管理 |

更新后的分类：睡眠、精力和心情属于首页常驻通用指标；围绕特定问题所需的更详细观察按需展开。通用常驻不等于每日强制填全，详见后续产品方案。

可自动生成的指标：已记录次数、已测量泵出总量、已记录瓶喂摄入、时间间隔、同条件趋势、覆盖时间窗、缺失字段。任何合计都需说明覆盖范围；“本日已记录”与“完整 24 小时”不同。

不生成：用亲喂分钟换算摄入量、把泵出量当总产奶量、把妈妈泵出量与宝宝摄入量相加、仅凭一次泵奶推断供给不足、基于未观察的空值生成正常结论。该组为产品数据语义约束。

## 4. 待记录指标的选择规则

1. **明确当前目标。** 用户选择“我担心宝宝没吃够”“我喂奶疼”“我想为返工做准备”等；对话识别到的目标先让用户确认，避免系统私自添加疾病标签。
2. **先识别需要及时帮助的情况。** 明显进食困难、有关摄入不足的担忧、全身症状或恶化等进入相应专业帮助路径；具体分级、年龄条件和时限由临床负责人依据适用指南制定。安全相关入口不依赖付费状态，不因未填完表单而阻挡。
3. **按喂养方式和已有事实筛选。** 纯亲喂用户不显示“今日泵量不足”；返工计划不用默认追问每天心情；不要求正常用户为了获取泵量而额外泵奶。
4. **复用并去重。** 同一次亲喂关联妈妈和宝宝，Me 与 Baby 均可访问；双侧泵奶属于一次 session；多个问题共享尿便、体重等事实。来源不明的历史记录不能只凭时间接近自动合并。
5. **通用常驻、专项按需。** 后续方案确定通用区固定展示，此处的少量优先项仅适用于专项区；更多观察分步展开，不将展示数量当作临床硬上限。每项写明“为什么需要”和对应时机。
6. **按事件、变化或复评时间出现。** 不把按次记录、一次性背景和低频测量全部转换成“今天未完成”。允许“现在不方便”“没有观察到”“不再关注”。
7. **观察有期限。** 每个观察计划定义复评日期/条件；用户确认问题改善、专家调整方案或目标结束后降频或归档，保留随时求助入口。
8. **数据不足时给出具体缺口。** 用“这里是今天已记录的 3 次泵奶，尚不能代表完整一天”，代替“奶量下降了”。反馈对应用户问题，而非单纯增加打卡进度。

一次“待记录项”的产品定义至少包含：关联问题、关联母婴、指标组、提出原因、触发条件、时间窗/复评条件、已有数据状态、是否可跳过、来源（用户/专业计划）、完成后的反馈去向。可追溯依据应可供专家检查；用户界面不需要展示技术字段。

## 5. 首页示例

**用户关注：我担心宝宝没有吃够。**

首页显示“为了解宝宝近期的喂养情况”，复用已登记的日龄、喂养方式和测量资料。按已有数据缺口选择“补充最近一次喂养”“记录接下来观察到的尿湿”“补充已有的体重测量”。没有体重数据时允许“目前没有”，不暗示必须现在购买秤或自行每日称重。说明何时可与专业人员一起复评；有令人担忧的表现时直接提供求助路径。[CDC](https://www.cdc.gov/infant-toddler-nutrition/breastfeeding/newborn-basics.html)

**用户关注：这两天喂奶疼。**

先了解部位、发生阶段和影响；选择一次有代表性的喂养记录疼痛与含乳情况。下一次反馈围绕同一症状是否变化、是否已获得帮助。泵奶量、心情、库存不默认加入。

**用户关注：下周返工。**

先显示返工日期、离家时间和可用泵奶窗口；随后只补计划需要的泵奶、瓶喂接受与交接信息。回报是可执行的安排和实际记录对照，不是“再多存一些奶”的无上限目标。[CDC](https://www.cdc.gov/breastfeeding/features/returning-to-work-and-breastfeeding.html)

## 6. 当前 App 能力与缺口

以下结论来自 App 领域模型的静态核对，不等同于完成后端、设备连接或专家端验收。

| 当前能力 | 已有字段 | 对本方案的缺口 |
|---|---|---|
| 妈妈泌乳记录 `lib/domain/lactation/lactation_record.dart` | 泵奶/亲喂、时间、左右侧、泵量或亲喂时长、舒适/涨/疼/不确定、备注 | 泵奶时长、双侧 session、设备设置、结构化疼痛和症状、关联宝宝/共同事件 |
| 宝宝喂养 `lib/domain/baby/baby_record.dart` | 亲喂/母乳瓶喂/配方奶、时间、亲喂侧别/时长、瓶喂量、备注 | 含乳/吞咽观察、接受情况、泵出与摄入关联语义、提供量和实际摄入区别 |
| 宝宝尿便与生长 | 尿湿/便便/两者、便色/性状/异常；体重/身长/头围及日期 | 测量来源/条件、按问题共享观察时间窗和记录完整度 |
| 宝宝资料 `lib/domain/baby/baby_profile.dart` | 出生日、性别、喂养方式 | 孕周/早产背景等有需要时补充的信息；不用让全部用户填写完整临床档案 |
| 妈妈日记 `lib/domain/mother/mother_diary.dart` | 睡眠、精力、身体不适、心情与支持等 | 当前是通用日记，不是泌乳专项症状观察；不宜直接当低供给判断依据 |

关键数据关系：妈妈亲喂和宝宝亲喂目前分别建模，不能仅改 UI 就宣称已经去重共享；需要明确共同事件、权限、编辑/删除同步与历史数据处理。现有泌乳汇总按记录条数计数，后续按 session 统计时要明确双侧数据的迁移和兼容规则。

## 7. 分期建议与验收

先做指标字典和显示规则，再调整首页。首期建议验证四个入口：担心没吃够、喂奶疼/含乳困难、泵奶问题、返工准备；它们复用度高，也能验证按需求记录是否比固定打卡有效。此为产品取舍，尚非来自真实咨询频率的数据结论。症状相关求助与临床边界在首期共同考虑。

泌乳过多、减奶/断奶和恢复泌乳沿用共用记录能力，再增加相应计划与复评；舌系带保留为专业评估分支。避免将 12 个问题做成 12 套互不共享的表单。

验收应覆盖：同一事件只填一次；纯亲喂无需泵量；未知不当作零；双侧计一次 session；部分日记录不与完整日直接比较；问题结束可以停止提醒；专家能看到原始记录和来源；用户能解释为什么被要求记录。

产品验证指标建议：首次获得有用反馈的时间、单次录入负担、与问题相关记录的完成率、用户自报反馈是否有帮助、重复填写率、无关提醒率、复评是否完成。稳定后少记录也可能是成功，不能只以记录次数增加衡量效果。

下一轮临床与用户核验需分别确认：各入口的最低必要信息；具体警示和转介规则；年龄/早产适用范围；复评频率与停止条件；用户可接受的记录负担。上述确认影响正式产品规则，不阻止先用原型验证理解和操作成本。
