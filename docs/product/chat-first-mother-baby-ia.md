# Chat-first 侧边栏「妈妈 / 宝宝」信息架构与界面方案

状态：第一期 Flutter 页面已落地；静态预览仍是设计示例，非真实账号内容或临床内容审核。配套可检视静态示例：[`chat-first-mother-baby-preview.html`](chat-first-mother-baby-preview.html)。示例数字与姓名均为虚构排版数据，不连接账号、接口或记录。

## 设计判断

两个目的地不是账户设置页，也不应把妈妈和宝宝的记录揉成一份“家庭健康评分”。妈妈页回答「我填过什么、最近感觉如何、吸奶记录在哪里」；宝宝页回答「当前看的是哪个宝宝、今天记录了什么、测量如何随时间变化」。侧边栏已用「妈妈」替代含义模糊的「我的」，「账号与设置」保留在更多服务。

概览只陈列已保存事实；“未记录”“资料未填写”“读取失败”“记录不完整”是四种不同状态。首屏给身份、最近记录与下一步；长表、完整历史和编辑表单向下一层展开。所有日期和日龄使用账号时区；多宝宝切换需同步当前宝宝上下文。其他家庭身份能看到什么敏感妈妈数据，须按现有授权契约决定，不能因入口可见就默认可见。

## 页面地图与首屏优先级

```text
侧边栏
├─ 妈妈 /me
│  ├─ 身份与阶段（已确认日期才显示产后日龄）/ 资料入口
│  ├─ 最近状态（睡眠、精力、心情）/ 记录我的状态
│  ├─ 吸奶：今日已记录次数与奶量 / 近 7 天趋势表
│  ├─ 我的关注点
│  └─ 资料详情与历史 / 独立的旧版泌乳管理
└─ 宝宝 /baby
   ├─ 当前宝宝与切换 / 出生日期、日龄、喂养方式 / 编辑
   ├─ 今日照护：喂养、湿尿布、脏尿布、睡眠 / 记一笔
   ├─ 生长：最近测量值和日期 / 趋势与逐笔数据
   └─ /baby/details 完整记录与管理
```

**妈妈首屏**：页眉「妈妈」→ 身份摘要 →「最近的我」三项已记录状态 → 吸奶摘要。已保存资料以紧凑网格置于页首；独立的资料编辑入口仍需后续契约。关注点显示已保存标签，不用标签推断健康状况。对孕前/孕期/未确认分娩日期的账号，不强行显示“产后第 X 天”。

**宝宝首屏**：页眉「宝宝」→ 当前宝宝选择器/身份摘要 → 今日照护四项。生长位于下一屏，记录日期与单位必须始终紧邻数值；资料编辑及完整记录明确为二级操作。不重复聊天首页的逐日长文案。

## 趋势表的呈现规则

| 位置 | 默认可视内容 | 详细表格 | 当前数据与依赖 |
| --- | --- | --- | --- |
| 妈妈·吸奶 | 最近 7 个自然日的逐日**已记录奶量**，有记录且奶量完整才绘制该日柱形；上方独立显示今日次数 | 日期、已记录次数、已知奶量（ml）、完整性；缺失记「未记录」，部分填写记「奶量未填全」，不画成 0 | 现有 `getMilkTrend` 是 7 天；`getPumpingToday` 的数量与可计算奶量来自当前账号。缺失天与不完整页不可报精确平均值 |
| 妈妈·状态 | 最近两天为日期列表及三个状态标签，不画“心情分数线” | 日期、精力、睡眠、心情及记录时间 | 当前 `getWellbeing` 只读近两天。7/30 天表为后续数据契约，不在当前实现上伪造 |
| 宝宝·今日照护 | 当天四项已保存记录次数；不把 0 次记录解释为“没有发生” | 按账号日界划分的 7 天分页趋势表，按「喂养 / 尿布 / 睡眠」逐项切换，日期+次数+记录完整性 | 当前 `BabyHomeController` 通过已实现的完整分页读取近 7 天记录并按账号时区聚合；读取失败不显示数值 |
| 宝宝·生长 | 最近一次有效测量及日期；**至少 2 个不同日期的数据点**才用折线表示个人变化 | 指标切换：体重（kg）、身长/头围（cm）；每行测量日期、值、单位，可回到原始记录 | 当前 `/baby/details` 有生长曲线、最新记录和出生至 6 个月的曲线范围；若要跨全年展示，需扩展查询/参考范围。不能把自家曲线标成诊断结论 |

图与表是同一组已保存数据的两种读法：图负责扫视变化，表负责精确读数。手机窄屏采用**单指标图 + 两/三列表格**，不把喂养、尿布和睡眠混入多纵轴图。断档不连线，单位不省略；屏幕阅读器可顺序读取表格。参考区间若展示，须标清来源、适用前提及非诊断属性；不满足前提时只画宝宝自己的测量点。

## 页面呈现与交互

- **视觉**：沿用 `MomHomeTokens` 的暖白背景、深色正文、玫瑰色主动作、薄边框；宝宝的趋势使用青绿色区别妈妈，但颜色不单独承担含义。页标题 24、区标题 17–18、正文 14–16，辅助信息不低于可读的正文层级。数字等宽对齐。大块信息靠留白和分隔组织，不每一行套卡。
- **表格密度**：顶部先给「当前值 + 记录日期 + 状态」，趋势卡中可放 7 日紧凑行。完整记录页使用按日期排列的可滚动表；行点击查看原始记录。指标切换保留日期范围，切换宝宝则清掉上一个宝宝的图表与选择状态。
- **主要操作**：妈妈为「记录我的状态」/「查看吸奶记录」，宝宝为「记一笔」/「查看全部记录」。编辑资料放身份卡的次按钮。操作成功后更新相应区块，不静默把其他区块当已同步。
- **状态**：首次无资料显示「添加资料」；资料已有但今天未记显示「今天尚无记录」；数据读取失败显示「暂时无法读取 · 重试」；部分记录显示不完整提示并禁用误导性的合计。非妈妈身份不展示个人状态详情，应给清楚的权限说明。
- **可访问性**：44–48 px 触控目标；大字号时卡片与表格纵向排布；曲线旁保留日期/数值列表；减少动态效果时不依赖图表动画说明变化。

## 落地分期与验收

**第一期：已实现。** `/me`、`/baby` 的信息层级已重组；妈妈吸奶 7 天图表、宝宝近 7 天照护表与现有 0–6 月生长曲线/逐笔测量表使用真实账号数据；妈妈资料缺字段显示「未填写」。妈妈资料、状态、吸奶与趋势读取统一按账号时区取日。保留现有 `/baby/details`、`/me/lactation` 作为二级入口。无宝宝记录不是健康结论，7 天读取不完整时整块不显示数字。

**第二期：尚未实现。** 妈妈资料独立编辑、更长时间的状态历史、六个月后的生长曲线与参考范围，需要扩展数据契约、权限及回写路径；目前超过六个月仅展示当前宝宝最新测量值与日期，并明确提示曲线范围。不得用静态示例值填补接口空白。

验收走查：320/390/430 宽与 2× 文字；无资料、单条、连续多条、缺一天、部分奶量、读取失败、切换宝宝、跨日、非妈妈身份；趋势图所示每个点必须能在表格/原始记录找到同一日期与数值。最终临床含义与隐私授权由对应产品/专业评审确认。
