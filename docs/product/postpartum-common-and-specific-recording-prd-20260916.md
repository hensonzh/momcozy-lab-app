# 产后首页：通用指标 + 按需专有指标

版本：v1 产品方案；日期：2026-09-16。
依据：用户确认的“两类指标、通用常驻、问题与目标主动选择”的方向。
交付范围：产品定义、指标分类、信息架构、交互和验收要求。尚未实施 Figma、App 或后端变更。

## 1. 产品定义

首页持续帮助用户了解产后日常状态，同时围绕用户主动选择的身体问题和管理目标提供专项记录与跟进。

核心公式：

**首页记录内容 = 适用的通用指标 + 已启用问题/目标所需的专有指标。**

通用指标不依赖用户有没有身体问题；专有指标需要有明确使用场景。同一指标只定义、记录一次，可以服务多个问题和目标。

“通用”表示值得持续关注、默认可见，不意味着每天必须填全，也不意味着所有产后用户的喂养方式相同。“专有”表示按需启用，不等同于罕见或不重要。

本方案以产后妈妈的 Me 首页为主体，泌乳与喂养作为第一期重点。宝宝事件由 Baby 记录体系承载，首页引用同一份数据。非泌乳的复杂产后专项管理需要另行完善专业内容，不在首期假装提供完整治疗计划。

## 2. 两类指标与分类原则

### 2.1 通用指标

建议保留四个用户熟悉的展示主题，其中身体与精力、休息、心情适用于产后妈妈；喂养与泌乳按实际喂养方式适配。

| ID | 首页主题 | 最小记录字段 | 输入方式与时机 | 记录后的展示与用途 |
|---|---|---|---|---|
| C01 | 身体与精力 | 当日精力；可选“有新的不适” | 精力三档；按日轻量记录，允许当日更新 | 显示“有力气/还撑得住/很疲惫”等自报状态和可比较的历史；不虚构恢复百分比 |
| C02 | 昨夜休息 | 昨夜睡眠总时长区间；可选休息后感受 | 沿用时长区间；按日记录、允许不确定 | 比较相同时长区间；区间数据不显示精确“少 1 小时” |
| C03 | 今日心情 | 当前心情；可选需要支持 | 一次点选，后续可补充 | 显示本人的选择；需要支持时提供倾诉或求助入口，不将简单选项当作诊断量表 |
| C04 | 今日喂养与泌乳 | 实际发生的喂养/泵奶：时间、方式、侧别（适用时）、实测量或可选时长 | 按事件记录，可复用设备/已有记录；不要求亲喂填写毫升 | 分开显示亲喂、泵奶、瓶喂已记录情况；服务日常回顾和后续专项管理 |

这些主题参考产后照护中对睡眠与疲劳、情绪、身体恢复、婴儿照护和喂养的关注范围。**上述四张卡片、录入时机和字段选择属于产品设计，不是指南要求所有人每日打卡。** 参考 [ACOG 产后照护](https://www.acog.org/clinical/clinical-guidance/committee-opinion/articles/2018/05/optimizing-postpartum-care) 与 [WHO 常规产后照护](https://www.who.int/publications/i/item/9789240045989)。

通用字段的适配规则：

- 有亲喂或泵奶行为时，Me 显示“今日喂养与泌乳”，泵出量、亲喂次数/时长分别表述；不将所有量混合成“今日奶量”。
- 仅瓶喂且不泌乳时，显示“今日喂养”，引用 Baby 的瓶喂事件；不显示“泵奶未完成”。
- 用户明确不适用喂养记录时，允许隐藏喂养主题；身体、休息、心情仍是通用首页内容。未知喂养方式时先确认，不能当作不适用。
- 身体卡中的“有新的不适”仅用于发现关注需求，不展开每天必填的疼痛、伤口等全量表单。
- 时间、对象、单位和来源属于记录上下文；日龄和产后天数从已有资料计算，不要求每日重填。
- 妈妈体重、每日体温、饮水量、热量、泵量目标不纳入首期所有用户默认必填指标。宝宝体重在 Baby 可随实际测量记录，在需要增长观察时才提升到 Me 专项跟进。

### 2.2 专有指标

专有指标必须回答“为什么这位用户现在需要记录它”。支持身体问题触发，也支持没有问题但有规划目标的用户启用。

| 记录组 | 专有字段 | 启用来源 | 同时复用的通用数据 |
|---|---|---|---|
| S01 疼痛观察 | 部位/侧别、开始时间、发生阶段、程度、影响、变化 | 喂奶疼、泵奶疼；减轻疼痛目标 | 喂养事件、身体与精力 |
| S02 含乳与喂养表现 | 是否含住、反复掉乳、吞咽观察、点击声、喂后乳头变化 | 含乳困难；喂养更舒适 | 亲喂时间、方式、侧别 |
| S03 宝宝摄入与增长观察 | 有日期的体重及来源、尿便观察、补充喂养、相关进食表现 | 担心没吃够；了解摄入与增长 | 已记录喂养和实际瓶喂摄入；Baby 已有尿便和体重 |
| S04 乳房症状变化 | 红/肿/硬痛位置和趋势、破损、已测体温、全身不适、就诊反馈 | 乳房不适；相关专业观察计划 | 泌乳事件；S01 疼痛共享 |
| S05 泵具与设置 | 型号、左右罩杯尺寸、模式/档位、摩擦/漏气、设置变更 | 泵奶不舒服/效率困扰；优化泵奶 | 泵量、时长、时间和侧别 |
| S06 奶瓶/亲喂接受情况 | 接受/部分接受/拒绝、喂养者、环境、姿势、奶嘴及流速 | 拒乳/拒瓶；返工准备 | 最近喂养与实际摄入 |
| S07 返工与储奶安排 | 返工日期、离家时间、泵奶窗口、储奶批次/取用、交接安排 | 返工/母婴分离目标 | 泵奶和瓶喂事件 |
| S08 调整与复评 | 用户目标、既有方案、调整点、执行情况、舒适度变化、复评日期 | 减少泵奶/断奶、恢复泌乳、专业供给管理 | 现有喂养、症状和摄入观察 |
| S09 休息细节 | 夜间中断、最长连续睡眠、影响休息的原因、可获得的照护支持 | 主动选择改善休息 | C01 精力、C02 睡眠 |
| S10 情绪支持细节 | 主要压力来源、生活影响、支持感受 | 主动选择获得情绪支持 | C03 心情 |

补充说明：

- S03 的“专有”指 Me 首页何时启用这一观察集合；尿便和体重在 Baby 的基础记录能力继续保留，不要求 Baby 用户必须先选择问题才能录入。
- 泵奶量、时长等通用字段被专项复用后仍为同一指标，不能复制成“日常奶量”和“追奶奶量”。
- 通用的身体自报与专有疼痛量表不同；“有新的不适”不等于每天要求填写疼痛分数。
- 疼痛不限定为乳房疼痛，但首期只有完成对应内容设计的泌乳相关问题可启用完整专项；其他部位不套用泌乳模板。
- 泌乳专项分类与来源详见[问题—指标盘点](lactation-needs-and-recording-matrix-20260916.md)。其中原先将通用日记完全按问题启用的建议，由本方案替代。

## 3. 身体问题与管理目标分别选择

**身体问题：我现在遇到了什么。管理目标：我希望接下来改善或准备什么。** 两者可独立存在，可多对多关联。

### 3.1 身体问题的用户表达

首期选择项：

- 喂奶或乳头疼。
- 乳房胀、硬或不舒服。
- 宝宝含不住、容易掉乳。
- 担心宝宝没有吃够。
- 感觉奶量比之前少。
- 泵奶不舒服，或觉得泵不顺。
- 宝宝不愿亲喂或不接受奶瓶。
- 经常喷乳、涨奶，宝宝吃奶容易呛。
- 其他困扰／暂时说不清。
- 目前没有明显困扰。

“目前没有明显困扰”与具体当前问题互斥。“暂时说不清”可先描述，不自动归为任何疾病。“乳腺炎、真实低供给、舌系带异常”等专业结论不作为要求用户自诊的首层选项。已有专业诊断可作为单独的专业资料，并标记来源。

### 3.2 管理目标

完整目标目录（按第 10 节分期开放）：日常了解状态、喂养更舒适、了解宝宝摄入与增长、了解并改善奶量、泵奶更舒适/更方便、准备返工、逐步减少泵奶/结束哺乳、尝试恢复泌乳、改善休息、获得情绪支持。

可选择多个目标，并指定一个当前最关心的目标用于排序；不限制用户实际存在的问题数量。目标不自动生成治疗方案。

“增加奶量”与“减少奶量”同时被选中时，先澄清时段、原因与期望，不同时下发互相冲突的记录/行动建议。选择问题不自动勾选目标；可推荐目标，由用户确认。

### 3.3 选择流程

入口：首次进入 Me 的轻量邀请卡、首页“我的关注”编辑按钮、相关记录完成页、Cozymate 对话中的确认卡。主入口留在 Me，More 只可提供快捷链接，不形成第二套健康资料。

1. **确认适用背景。** 复用产后阶段、宝宝和喂养方式，仅补缺失项。
2. **选择目前的困扰。** 多选，也可选“目前没有”或“以后再设置”。
3. **选择管理目标。** 与问题分开；选返工才补返工日期，选疼痛才补侧别等必要上下文。
4. **预览首页变化。** 明示“通用记录保持展示；将增加疼痛、含乳观察”等，并解释用途。按钮“应用到首页”。
5. **设置提醒偏好。** 独立选择是否提醒、时间与免打扰；启用专项不自动等于接受推送。

跳过设置可以直接使用通用记录。跳过是“尚未设置”，不能保存成“没有问题”。用户后续随时可修改。

AI 可以建议“要把喂奶疼加入关注吗？”，只有确认后才长期改变首页。用户直接开启一次专有记录可即刻保存该次记录；是否持续展示另行确认。

## 4. 问题与目标到记录组的规则

| 用户选择 | 新增/启用专有组 | 规则说明 |
|---|---|---|
| 喂奶疼／喂养更舒适 | S01；含乳相关时 S02 | 复用亲喂事件，不重复记录一场喂养 |
| 含不住、掉乳 | S02；报告疼痛时 S01 | 摄入担忧存在时再加入 S03 |
| 担心宝宝没吃够 | S03；有亲喂困难时 S02 | 复用 Baby 的尿便/体重，不重复建一套 |
| 感觉奶少／了解并改善奶量 | S03、S08；实际泵奶且需排查设备时 S05 | 通用泵奶/亲喂记录直接复用；不用单次泵量确诊 |
| 乳房胀硬痛 | S04、S01 | 专业求助优先于完成记录；不展示“揉散”“排空达标”任务 |
| 拒乳／拒瓶 | S06；需要了解摄入时 S03 | 根据拒绝对象展示对应观察项 |
| 泵奶不适／优化泵奶 | S05；报告疼痛时 S01 | 优先复用设备档案，只有变化时重填 |
| 返工准备 | S07；需要奶瓶适应时 S06 | 没有身体问题也可启用 |
| 奶多、喷乳、反复涨 | S04、S08；按表现补 S02/S03 | 引导专业评估，不自动生成减供给处方 |
| 减少泵奶／断奶 | S08；不适时 S04 | 目标和既有安排由用户或专家明确 |
| 恢复泌乳 | S08、S03 | 保留摄入保障信息；不承诺恢复时限 |
| 改善休息 | S09 | 不重复添加 C02 睡眠卡 |
| 获得情绪支持 | S10 | 日常心情选项不替代专业筛查 |

舌系带相关担忧作为含乳/摄入困难中的专业评估分支，不提供用户照片自动确诊或手术选择流程。参考 [AAP 舌系带说明](https://www.healthychildren.org/English/news/Pages/AAP-report-addresses-rise-in-tongue-tie-diagnoses-for-breastfeeding-concerns.aspx)。

## 5. 首页信息架构与交互

自上而下：

1. 问候与产后阶段。
2. “我的关注”摘要：当前问题标签、主要目标、编辑入口。
3. Cozymate 摘要：已有事实、适用的变化、可继续的对话。没有真实分析结果时不展示伪造分析，也不承诺记录后一定立即获得尚未上线的服务。
4. 通用区“今日记录”：喂养与泌乳 + 身体与精力 + 昨夜休息 + 今日心情。保留当前基础卡片和背景语言，固定顺序。
5. 专有区“当前关注”：按已启用记录组展示，说明“因为你关注……”。无专项时只保留轻量设置邀请，不摆放一排未启用的空指标卡。
6. 专家陪伴计划：已有服务展示实际复评/咨询入口，无服务按当前产品入口展示。
7. 统一底部导航，沿用现有五个 Tab。

普通情况下，专有区默认展开主要目标相关的两张卡，剩余显示“其他关注（N）”；数量是待原型验证的展示约束，不能吞掉其他问题。需要及时处理的健康提示可置顶，不能被折叠或营销内容遮挡。

### 5.2 记录流程

- 通用日记优先一项快速输入，其余可展开；不为了保存心情而要求把睡眠、精力填完。
- 专有指标可以在相关通用事件表单中追加，例如一次亲喂后可补疼痛/含乳观察，保存后同时更新通用区与专项区。
- 专有卡片也能独立补充症状；不要求每次疼痛记录都伪造一条喂养事件。
- 首页专有卡显示最近观察、更新时间、适用的变化和下一次记录原因；不只显示“未完成”。
- 保存成功后提供事实反馈和下一入口；输入不足只说明缺口，不输出不受数据支持的诊断或确定因果。

## 6. 指标展示与记录状态

指标分类与展示状态分开。某项专有指标暂不显示，不等于不支持记录；结束关注不删除历史。

| 情况 | 首页行为 | 数据行为 |
|---|---|---|
| 未设置问题/目标 | 通用区正常展示；轻量邀请选择关注 | selection 状态为未设置，不能推断无问题 |
| 明确无问题、无专项目标 | 展示通用区 | 保存用户选择，可随时修改 |
| 无问题、有返工等目标 | 通用区 + 对应专有组 | 允许目标独立激活记录组 |
| 有问题、暂不确定目标 | 通用区 + 问题对应观察 | 可先记录，不强制选治疗目标 |
| 多问题共享指标 | 展示一个共享记录入口，说明服务哪些关注 | 同一事实关联多个问题/目标，合计只算一次 |
| 新增专有组，已有相关记录 | 展示有来源和时间的历史或当前事实 | 仅在对象、时间窗、字段语义一致时复用；旧记录不自动算今天完成 |
| 新增专有组，没有数据 | 展示“首次补充”及用途 | 空值保留为未知 |
| 暂停关注 | 从活跃专有区移除，停止对应提醒 | 历史保留，可恢复 |
| 问题改善/目标完成 | 用户或专业计划确认后归档 | 不由“数天没记录”自动判断康复 |
| 删除一个问题，但另一个目标仍需该指标 | 保持共享指标展示 | 重新计算仍有效的关联 |
| 数据加载失败 | 通用卡和关注配置尽可能独立展示，局部提供重试 | 不把失败显示为“无记录/无问题” |
| 修改关注保存失败 | 保留原生效配置和本次选择，提示重试 | 不宣称应用成功，不发出新提醒 |
| 更换账号或宝宝 | 按正确身份/母婴关系重新读取 | 不沿用上一位用户或另一宝宝的专有记录 |

每个记录项需区分：未记录、不适用、不确定、已记录、载入失败。日汇总、按次记录、一次性资料和专业复评四种节奏不能混用同一每日完成度。

可以显示“今日已记录 2 项”，但不把所有通用和专有指标合成一个永久欠账的 N/M。泵奶与亲喂属于事件流，不存在对所有人的统一每日应完成次数。

## 7. 提醒、趋势与反馈

- 通用记录提醒与专有提醒独立设置，默认不因首次开启关注而自动推送。
- 多个问题共享同一项记录时合并提醒；同一时间窗已有记录则不重复催促。
- 专有组必须定义复评日期或复评触发条件；一次性信息完成后仅在变化时再问。
- 趋势只比较对象、单位、时间窗和记录条件合理可比的数据；区间睡眠不生成精确小时差；未记录不是零。
- 泵出量与宝宝摄入量分开；亲喂时长不换算毫升；部分日泵量不与完整日泵量直接宣称升降。
- 目标不同，反馈也不同：返工关注安排是否可行，疼痛关注体验变化和求助，减少泵奶关注既有安排及舒适度，不统一追求奶量增长。
- 日常情绪与身体自报不是疾病筛查结果；若引入标准化筛查工具，应独立标记版本、用途与后续支持路径。

异常信息不必等用户先把相应问题加入关注才响应；用户主动选择控制首页长期内容，不能成为及时求助提示的开关。具体触发条件需对应专业规范，例如 [CDC 产后紧急警示症状](https://www.cdc.gov/hearher/maternal-warning-signs/index.html)，并由临床负责人确认产品规则；本方案不新增未核验阈值。

## 8. 最小产品数据对象

这里只定义产品语义，具体数据库/API 设计留到实现方案。

- **指标定义**：唯一 ID、名称、通用/专有分类、适用人群、输入类型/单位、所属记录组、记录节奏、展示方式。
- **关注事项**：用户选择的问题或目标、关联妈妈/宝宝、起始时间、状态（进行中/暂停/已结束）、主要关注标记、来源与确认时间。
- **展示配置**：已启用记录组、启用原因、关联关注、排序、提醒偏好、复评条件。不是重新复制一套指标值。
- **事实记录**：实际时间/日期、对象、原始值、来源、可选事件关联、版本。用户输入、设备数据、专家观察分别标识。
- **观察/支持计划**：涉及的关注、复用的指标、补充项、提出者、版本、复评安排；专家计划不能被用户目标悄悄覆盖。

母婴共同事件需要有明确关联：Me 和 Baby 展示同一亲喂事实；一次双侧泵奶按同一 session 组织，单侧量与双侧合计不能重复相加。历史数据不靠时间接近强行合并。

## 10. 设计与实施范围

第一期完整做通用记录与关注管理框架，贯通四个专项：疼痛/含乳、宝宝摄入担忧、泵奶问题、返工准备。其余泌乳目标复用同一指标体系继续扩展；S09/S10 的字段可利用现有日记，但完整支持内容需独立验收。不在 UI 暴露尚不能完成记录和反馈的空目标。

Figma 需要覆盖的关键画面：

1. 未设置关注、通用无记录。
2. 明确无问题、通用已记录。
3. 无问题、有返工目标。
4. 喂奶疼/含乳困难，新增专有卡。
5. 多问题共享指标与折叠。
6. 问题选择、目标选择、应用预览。
7. 亲喂事件补充疼痛/含乳信息。
8. 专项独立记录与历史详情。
9. 暂停、恢复、结束关注。
10. 部分记录、加载失败、配置保存失败。
11. 不同喂养方式与母婴对象切换。
12. 需要及时帮助的信息展示。

后续 App 实现顺序：指标字典和规则 → 关注配置与持久化 → 通用/专项记录复用 → 首页展示 → 提醒与复评 → 专家/AI 有依据的反馈。设计稿和真实能力共同验收，不能只增加展示卡片。

## 11. 验收与产品验证

功能验收：

- 没有身体问题的用户仍能完整使用通用首页。
- 不选择问题可以选择目标；不确定目标也可以记录已选择的问题。
- 用户确认后专有卡才长期出现，取消选择可以恢复原配置。
- 同一指标、同一事件在通用/专有区和 Me/Baby 中不重复录入与统计。
- 暂停/结束关注停止对应提醒，历史可查看；共享指标有其他有效关联时保留。
- 非泌乳用户不会收到泵奶任务；亲喂用户无需提供估计毫升。
- 没有输入不能推断正常，无数据不能推断无问题，读写失败不能伪装成功。
- 首页基础区顺序稳定，动态卡扩展不改变统一导航。
- 没有真实分析结果时只显示真实记录摘要和可用支持入口。

用户验证关注：用户能否区分通用记录与专项记录；能否解释专有卡为何出现；设置问题/目标是否容易；单次记录耗时；重复填写率；提醒相关性；记录后是否获得有用反馈。所有指标需按无问题/有问题、不同喂养方式及目标分组看。记录数量下降但目标完成、负担减少，也可能是正向结果。

原型阶段验证展示数量、首层字段和选择步骤的负担。临床负责人核对通用指标的适用范围、专有观察字段、求助规则和复评条件；这些是正式规则发布前的内容验收，不要求用户在当前讨论中逐条补充医学判断。
